# PF-005 implementation record

| Field | Value |
|---|---|
| Story | PF-005 — Start an isolated MCP session automatically from any directory |
| Delivery status | Repository implementation complete |
| Host entry point | Signed Go launcher `agentmemory mcp --agent <host>` |
| Transient entry point | Immutable `agentmemory-mcp-session --session-id <uuidv7>` image command |
| Persistent authority | Core SQLite session, checkpoint, receipt, event, identity, and indexing records |
| Derived authority | Neo4j and IDX-002 projections remain rebuildable and noncanonical |
| Session transport | MCP over stdio; stdout contains protocol frames only |
| Core transport | Fixed authenticated local contracts; the container addresses only `http://core:9411` |
| Credential lifetime | Maximum twelve hours, bounded heartbeat lease of at most 120 seconds |
| Workspace mount | Exact current directory to `/workspace`, read-only, `rprivate`, recursive read-only |
| Container identity | Fixed UID/GID 10001, no TTY, no published port, no Docker socket |
| Relational schema | `0035_pf005_mcp_sessions` |

PF-005 makes directory-aware memory an automatic consequence of starting any configured agent. The
launcher observes the host working directory, starts or restores only the installation-recorded local
runtime, proves the signed active release, mints a one-session credential, and runs a disposable MCP
bridge. The persistent Core never receives a raw host path or credential secret. The bridge never
receives installation credentials, provider credentials, database files, the Docker socket, or a
writable source mount.

## Clean Architecture boundaries

The implementation is split by capability and dependency direction:

- `internal/domain/mcpsession` owns immutable workspace identity, credential lease, execution plan,
  mount policy, container security policy, and closed validators. It imports no Docker, MCP, HTTP,
  filesystem, or operating-system adapter.
- `internal/application/mcpsessionapp` owns the startup, child-process, checkpoint, revocation,
  terminal-state, and compensation state machine. Its dependencies are capability-specific ports;
  no vendor or platform branch appears in the application service.
- `mcpsessionhost`, `mcpsessiondocker`, `mcpsessioncredential`, `mcpsessioncheckpoint`, `corehttp`,
  and `mcpsessionbridge` are outbound or inbound adapters. Each validates its own trust boundary and
  maps implementation failures to content-free typed failures.
- `nativeProductSessionFactory` is the composition root. It resolves only a signed Ready installation,
  exact active release pointer, verified runtime evidence, native protected paths, and fixed product
  topology before constructing the application.
- Python `operations.domain.mcp_session` and `workspace_checkpoint` own the persistent aggregate and
  checkpoint contracts. The application layer owns registration, lifecycle, staging, reconciliation,
  and recovery. SQLite, HTTP, indexing, privacy, and retrieval implementations remain adapters.
- `WorkspaceCheckpointRecoveryWorker` depends on a narrow reconciliation protocol, not its concrete
  handler. This preserves dependency inversion and permits deterministic retry/cancellation tests.

Import Linter enforces the repository's context and layer contracts. All constructors reject missing
or typed-nil capabilities so a partial composition cannot become a permissive runtime.

## Startup sequence and concurrency

`StartMcpSessionApplication` executes one ordered transaction-like sequence:

1. Validate the host command and acquire the installation-wide cross-process lock.
2. Load and authenticate the active release pointer and its exact manifest/image/network coordinates.
3. Address only the recorded Docker endpoint/context. Start a stopped supported local runtime through
   its existing native authority, then capability-probe it before Compose.
4. Ensure the exact signed Compose release is running and Core passes its readiness probe. Image,
   network, project, endpoint, or release substitution fails closed.
5. Resolve the logical and real current directory, device identity, keyed path fingerprint, and Git
   evidence without invoking a shell. Generate a new UUIDv7 session ID.
6. Mint 256 random credential bits, publish them under the native owner-protected credential root,
   send only the SHA-256 digest and scoped registration to Core, and receive durable registration.
7. Begin the bounded Core lease and create the transient container from the immutable execution plan.
8. Release the startup lock before owning the child stdio stream. Other agents can now start without
   sharing this session, mount, credential, or project identity.
9. Forward stdin/stdout byte-for-byte. Diagnostics remain on stderr. Heartbeats renew only the exact
   active lease.
10. On EOF, cancellation, signal, or child exit, perform the bounded checkpoint, revoke Core authority,
    delete the exact credential file, remove the transient container, and persist the terminal state.

Startup failures compensate in reverse authority order. Once credential registration exists, cleanup
always attempts Core revocation before protected-file deletion. A revocation, container-removal, or
terminal-save failure forces `interrupted`; the application cannot report `completed` after incomplete
cleanup. An expired active lease is recovered as revoked and interrupted by Core's bounded recovery
worker. Every step is replay-safe and all durable writers use optimistic revisions or content digests.

## Runtime and container security profile

The launcher uses argv-based process ports exclusively. Paths, image references, network names, and
session IDs are validated typed values and are never concatenated into a shell command. Docker mount
long syntax carries the exact source path, including spaces, Unicode, quotes, semicolons, backticks,
`$()`, brackets, Windows drive paths, and UNC paths without evaluation.

The immutable session plan requires:

| Control | Required value |
|---|---|
| Image | Signed active-release `mcp-session` OCI digest for the current architecture |
| Network | The installation's internal-only AgentMemory network |
| Workspace | Exact real directory → `/workspace`, `readonly`, `rprivate`, recursive read-only |
| Credential | Exact protected file → `/run/secrets/agentmemory-session`, read-only |
| Root filesystem | Read-only |
| Writable storage | Size-bounded `/tmp` tmpfs only |
| Linux capabilities | Drop `ALL`; add none |
| Privilege | `no-new-privileges`; never privileged |
| Docker authority | No socket, context file, credential store, or daemon API mount |
| Networking | No published port and no host listener |
| Process controls | No TTY; PID limit 128 |
| Resource controls | 512 MiB memory and one CPU in Docker nanocpus |
| Lifetime | `--rm` plus explicit removal verification |

Docker Desktop file-sharing denial and lack of recursive read-only support are typed startup failures;
the launcher never widens the mount, mounts a parent, retries writable, or asks the user to weaken
Docker settings. On platforms where recursive read-only cannot be proven, startup refuses any unsafe
nested mount. The container image contains only the bridge binary and required trust roots and runs as
UID/GID 10001.

## Directory, repository, and project identity

The host resolver preserves both logical and real paths only in process memory. Core receives a keyed
workspace fingerprint, device identity, and optional keyed Git repository/worktree fingerprints. Raw
host paths are absent from the Core registration, audit facts, API response, MCP resource, and logs.

Core resolves identity in this order:

1. an active Checkout path/alias or matching repository plus worktree evidence;
2. an active Repository fingerprint linked to exactly one Project; or
3. owner-authorized automatic provisioning of one privacy-safe Project, Repository, device, and
   Checkout in a serialized SQLite transaction.

Ambiguous identity fails with `AM_CONFLICT`; it is never silently merged. A missing Git directory,
external worktree metadata, submodule boundary, or incomplete Docker visibility produces explicit
`none` or `partial` Git/index coverage. It never causes a parent or sibling mount. Provisioning checks
the current installation, active Brain/principal, current owner grant, and security epoch before any
insert and appends a hash-chained `mcp.workspace.provisioned` audit fact.

## Session credentials and authentication

The credential adapter uses `crypto/rand` for a 32-byte secret. Unix publication uses descriptor-based
`openat`, `O_NOFOLLOW`, exclusive temporary creation, fsync, hard-link publication, directory fsync,
owner/type/mode/link-count/size verification, and a 0700 owner directory. Windows uses the native
protected-store/ACL adapter. Only the digest crosses the root-authenticated Core boundary.

The transient bridge can read only the fixed `/run/secrets/agentmemory-session` path. It rejects path
substitution, symlinks, nonregular files, wrong mode, wrong size, cancellation, and excess bytes. Core
authentication binds the bearer secret digest to the exact session ID and rechecks on every request:

- registration and active state;
- credential issuance/expiry and revocation;
- installation ID and current security epoch;
- active Brain and principal; and
- the current grant validity window, not merely the grant state at credential issuance.

Unknown, expired, revoked, stale-epoch, foreign, and current-grant-revoked credentials are
indistinguishable authentication failures. Secret bytes are zeroed after use and protected files are
deleted only after Core revocation.

## Checkpoint capture and automatic indexing

`WorkspaceScanner` records a bounded baseline after session start and computes only changed authorized
relative files at termination. It applies product ignore policy, blocks traversal and absolute paths,
refuses links and unstable files, enforces per-file and total byte limits, and reports partial coverage
instead of reading outside the mount. File bytes are cleared after transport.

The root-authenticated launcher posts the canonical checkpoint to Core before the source mount is
removed. Core verifies the active session/workspace fingerprint and encrypts the complete canonical
batch with AES-256-GCM before committing it. AAD binds session ID, workspace fingerprint, batch digest,
algorithm, and purpose. Rows also bind nonce, AAD digest, canonical digest, sequence, partial flag, and
change count. Exact retry is idempotent; divergent reuse fails closed.

The recovery pipeline then:

1. decrypts and authenticates one bounded page;
2. applies capture privacy policy to each change;
3. excludes denied paths, stores sanitized artifacts under the Brain key, and emits deterministic
   `file.changed`/`file.deleted` canonical events;
4. queues one IDX-002 run whose target is the exact checkpoint digest and whose authorization is
   re-resolved from current canonical scope;
5. validates the index-run acknowledgement; and
6. appends the immutable checkpoint receipt only after ingestion and projection scheduling succeed.

Persistent IDX-002 workers reconstruct the current sanitized manifest from checkpoint history. They
never need the original source mount. Coverage is `pending`, `indexing`, `complete`, `partial`, or
`degraded`; it is exposed by `brain_status` and never inferred optimistically.

The existing PF-004 encrypted host event spool remains the bounded fallback for normal agent event
hooks when Core is temporarily unavailable. A terminal workspace checkpoint itself is never reported
successful unless Core durably stages its ciphertext; failure therefore interrupts the session rather
than claiming continuity that was not persisted.

## Multi-agent recall

The bridge exposes the vendor-neutral tools `brain_status` and `recall_context`, plus the
content-free `agentmemory://session` resource. `recall_context` accepts operation, current/related/global
mode, temporal bounds, and output budgets only. Brain, actor, grant, project, repository, checkout, and
selected-project IDs are absent from its schema and cannot be injected by a caller.

Core derives every authorization coordinate from the authenticated `McpSession`. Current and related
scope use its canonical workspace. Global scope expands internally to only projects authorized by the
same current owner/admin grant snapshot. One authorization snapshot is used for resolution, preventing
TOCTOU scope mixing. The bridge calls only the fixed `http://core:9411` endpoint, follows no redirect,
rejects duplicate JSON keys and unknown fields, bounds the response to 32 KiB, and validates every
status, count, digest, UUID, token, and nested provenance field.

Every recalled item is marked `untrusted_historical_data: true` at the MCP boundary. Original producer
host/model/adapter/capture provenance is preserved, so a Gemini or Codex session can safely identify a
decision captured by Claude in another authorized Project. Newlines are allowed in content but rejected
in IDs, policy versions, classifications, timestamps, provenance tokens, and reason codes. The MCP
output schema closes every nested object with `additionalProperties: false`.

## Persistent schema and audit evidence

Migration `0035_pf005_mcp_sessions` creates append-only credential, snapshot, checkpoint-batch,
checkpoint-change, and checkpoint-receipt structures, indexes, and immutability triggers. Session
snapshot chains bind the previous digest and exact canonical record. Registration, lifecycle, and
workspace-provisioning transitions append idempotent hash-chained audit events in the same SQLite
transaction as their state change.

Raw paths, credential bytes, source plaintext, sanitized plaintext, prompts, recall queries, and
arbitrary exceptions are prohibited from session/API/audit records. Encrypted prepared artifacts use
Brain keys; checkpoint envelopes use the installation root key. Decoders reject duplicate keys,
noncanonical shapes, wrong types, wrong algorithm/key reference, metadata substitution, digest mismatch,
authentication failure, and foreign repository identity.
