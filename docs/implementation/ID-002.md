ID-002 preserves a Checkout only when deterministic host or Git worktree evidence proves continuity.
A moved or symlinked checkout keeps its UUIDv7 Checkout ID and advances its aggregate version. A
clone and every linked Git worktree receive distinct Checkout IDs while resolving to the same
Repository ID. Branch, HEAD, dirty digest, keyed remotes, real path, logical path, filesystem object,
common Git directory, and worktree evidence remain distinct observations rather than Repository
identity.

## Architecture and transaction boundary

- `identity.domain.checkout` owns the immutable observation, Checkout aggregate, closed
  `CheckoutObserved`/`CheckoutMoved` event types, optimistic version policy, and deterministic
  continuity policy.
- `identity.application.commands.observe_checkout` owns the authenticated, path-free command and
  orchestration. It depends only on Checkout UoW, repository, authorization, and UUIDv7 generator
  ports.
- `LocalDeviceIdentityAdapter` emits installation-keyed real-path, logical-path, volume, and
  filesystem-object fingerprints. It never returns an OS machine ID or raw persisted path.
- `GitCliIdentityAdapter` uses a configured absolute executable and argv-only subprocess calls. It
  emits keyed Repository, common-directory, worktree, remote, and dirty fingerprints plus validated
  branch and full HEAD object ID. Credentials and raw remote URLs never cross the adapter boundary.
- `SqliteCheckoutObservationUnitOfWork` acquires the canonical single-writer lock and starts
  `BEGIN IMMEDIATE` before authorization. Current grant validation, idempotency lookup, continuity
  lookup, compare-and-swap, event append, observation append, and commit therefore share one
  transaction and cannot race revocation.
- The production composition root wires the concrete SQLite UoW and system UUIDv7 generator. Domain
  and application packages import no SQL, FastAPI, host adapter, provider, or operations package.

## Continuity and separation rules

All automatic continuity requires the same Brain-scoped Repository and verified Device. One of these
closed evidence sets must then match:

1. exact non-null Checkout fingerprint;
2. exact non-null filesystem-object fingerprint and volume fingerprint; or
3. exact non-null worktree fingerprint and common Git-directory fingerprint.

Zero candidates creates a new Checkout. One candidate updates it. Multiple candidates fail with
`AM_CONFLICT`; AgentMemory never guesses or merges. An explicit stale expected version also fails.
The SQLite compare-and-swap repeats this guarantee at persistence level. The in-process writer lock
serializes local contenders, while the version predicate and uniqueness constraints protect the
canonical state from stale or out-of-process writers.

A real path change emits `CheckoutMoved` and records the previous keyed path. A logical symlink alias
whose resolved real path is unchanged emits `CheckoutObserved`. Revision, branch, dirty-state, or
remote-only changes also emit `CheckoutObserved`. Event and observation payloads contain only IDs,
closed types, versions, and keyed evidence.

## Persistence and migration

Migration `0004_id002_checkout_observation` extends Checkouts with aggregate version, logical path,
volume, filesystem-object, common-directory, dirty, and canonical remote-set evidence. It adds exact
continuity indexes and creates `checkout_observations`, uniquely keyed by Brain/operation ID and
Checkout/version. Database triggers reject every update or delete against observation history.

The migration evolves the existing PF-002 `domain_events` ledger to support general aggregate type,
ID, version, event type, canonical JSON, correlation, and causation while retaining all legacy
projection-source columns and rows. Unique Brain/aggregate/version and Brain/aggregate/correlation
indexes enforce event ordering and command idempotency. The downgrade is allowed only before an
ID-002 canonical event exists; otherwise it fails closed instead of deleting history.

## Security, privacy, and API behavior

`POST /v1/checkouts:observe` requires both the local capability credential and the exact active
actor/grant/Brain authorization. The strict request accepts only UUIDv7 values, keyed fingerprints,
validated Git state, and an optional positive expected version. It has no raw path, machine ID,
remote URL, environment, command, or arbitrary metadata field. Its response contains only Brain,
Repository, Checkout, and aggregate version. Typed validation, authorization, conflict, and
dependency failures map to content-free canonical problem responses.

The Git adapter bounds output, rejects non-UTF-8 and malformed object/remote evidence, suppresses
stderr, disables stdin, never invokes a shell, and HMACs remote URLs after credential-removing
normalization. Filesystem and Git stat failures cross the boundary only as content-free typed
dependency errors.
