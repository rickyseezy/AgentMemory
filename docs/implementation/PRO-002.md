# PRO-002 implementation record

PRO-002 installs language-neutral custom embedding and reranking adapters without importing adapter code into the daemon or exposing Docker to core.

| Concern | Implementation |
|---|---|
| Trust/domain model | `apps/launcher/internal/domain/provideradapter` |
| Wire framing/schema | `apps/launcher/internal/domain/providerprotocol` |
| Clean-architecture use case | `apps/launcher/internal/application/provideradapterapp` |
| Closed Docker Compose adapter | `apps/launcher/internal/adapters/dockercli/provider_adapter.go` |
| Authenticated host receipt journal | `apps/launcher/internal/adapters/provideradapterjournal` |
| Offline Sigstore image policy | `apps/launcher/internal/adapters/provideradaptertrust` |
| Canonical persistence | `0033_pro002_custom_adapters` |
| External manifest contract | `contracts/jsonschema/provider-adapter-manifest.v1.schema.json` |
| Reference OCI adapters | `conformance/provider-adapters/{python-reference,go-reference}` |
| Author/operator guidance | `docs/integrations/CUSTOM-PROVIDER-ADAPTER-SDK.md`, `docs/runbooks/PRO-002-CUSTOM-ADAPTERS.md` |

The implementation uses constructor-validated immutable domain values. The application depends only on narrow verifier, policy, runtime, conformance, and repository ports. The Docker adapter accepts only `DeploymentPlan`; it cannot accept or merge user Compose. Startup failure returns cleanup authority, and every post-start failure invokes cleanup with cancellation removed from the cleanup context. Canonical persistence is the final action.

Supply-chain verification loads every evidence object by digest, rehashes the bytes, verifies the OCI image signature/trust policy, and independently evaluates both SBOM formats, provenance, licenses, and vulnerabilities. Sandbox policy is installation-owned and can only reduce gateway access or resource ceilings.

The protocol enforces strict JSON-RPC 2.0 objects, four-byte framing, an 8 MiB limit, operation/profile/idempotency/trace identities, deadlines, classifications and purposes, ordered content IDs/results, exact dimensions, finite vectors/scores, bounded redacted errors, and defensive copies. Both single-message and persistent multi-frame decoders are tested; malformed framing is fuzzed.

The Compose document is deterministic JSON with one service and one external installation-scoped internal network. It sets a digest-pinned image, non-root user, read-only rootfs, no-new-privileges, all capabilities dropped, init, no restart loop, no-exec bounded tmpfs, and hard CPU/memory/PID limits. It has no environment, build, volume, port, privileged, host-network, or Docker-socket key.

All PRO-002 behavior was developed with tests first. Release gates require at least 80% code coverage; the repository target remains stricter where already configured.

## Release evidence

The completed implementation passed the repository-wide race suite, package and changed-line coverage gates at 80%, Go vet, Staticcheck, strict golangci-lint, architecture enforcement, module verification, dependency vulnerability scans, protocol fuzzing, OCI reference-adapter builds, and sandboxed Docker execution. The changed critical-code mutation campaign killed 158 of 177 mutants: 89.27% raw MSI and 90.29% covered-code MSI, both above the mandatory 80% threshold.
