## Architecture and invariants

IDX-002 extends the indexing bounded context without moving Git, SQLite, HTTP, Pydantic,
Tree-sitter, or embedding-provider concerns into the domain. `IndexPlan` is a pure deterministic
domain service. Start/status/cancel handlers and the two workers depend on narrow ports. Git,
SQLite, the local embedding provider, graph evidence lifecycle, and FastAPI are replaceable
adapters. Import-linter enforces the domain/application/adapters dependency direction.

The plan compares a complete current manifest with the last completed snapshot. Every current unit
has a repository-relative path, content SHA-256, byte length, generated classification, and cache
key. The cache key frames the path, blob hash, plugin version, grammar revision, query-pack digest,
extraction configuration digest, and privacy-policy version. Reuse requires both the content digest
and the complete path-sensitive cache key to match. A global parser/extractor lock change therefore
rebuilds affected units even when bytes do not change.

`IndexPlan.create` emits an ordered closed operation set: Add, Modify, Rename, Delete, and Reuse.
VCS rename/copy evidence is corroborative; content identity remains authoritative. Rename carries
the previous source-file, file-revision, and semantic identities and creates an immutable lineage
edge. Copy creates a new file revision with a copy lineage edge but does not invalidate the source.
Delete has no current content and invalidates its previous semantic identities. Generated content
is excluded deterministically unless the exact run policy opts in.

Plans, roots, lifecycle snapshots, cancellation receipts, snapshot bindings, lineage, dependency
edges, projection events, and delivery attempts are append-only. SQLite triggers reject update and
delete. A run root binds the exact Brain, Project, Repository, principal, role, source snapshot,
implementation fingerprint, and plan digest. Run progress is an append-only state machine:
Queued → Running → Completed/Failed, with Cancellable → Cancelling → Cancelled at an atomic file
boundary. The worker revalidates the recorded current grant before claiming or committing work.
It checkpoints after every operation, so a process restart resumes from the next ordinal without
duplicating effective state.

Start idempotency is resolved before inspecting mutable source state. Reusing an operation ID
returns the original durable run; a divergent run/operation identity is a conflict. Cancellation
also has an immutable operation receipt and never interrupts a transaction halfway through a file.
Status responses contain counts, coverage, failure code, state, and freshness only—never paths,
source, parser diagnostics, vector values, or credentials.

## Source inspection and cache behavior

`GitIncrementalRepositorySource` uses one fixed absolute Git executable and argv arrays without a
shell. Repository roots are supplied by a trusted composition boundary and never persisted. It
accepts only canonical repository-relative POSIX paths, bounds Git output, file count, file size,
and command time, rejects symlinks and file substitution, and verifies every read against the
planned SHA-256. An immutable commit read falls back to the exact Git blob only when the working
copy no longer matches. Dirty staged, unstaged, and untracked changes are normalized with rename
and copy detection. After the first manifest, unchanged files retain their prior hashes and only
VCS-changed paths are opened.

The Git adapter belongs at the ephemeral workspace/session boundary. It is intentionally not
composed into the persistent Core because the signed architecture forbids a persistent source-tree
mount. PF-005 composes that boundary with the transient `/workspace` scanner and canonical changed
artifact streaming; the IDX-002 application port does not depend on a host path or Docker mount.

Incremental snapshot bindings make every completed snapshot complete even though only changed files
create new revisions. Reused bindings point to the immutable earlier revision; renamed/modified
bindings point to the newly parsed revision. Historical provenance remains intact, and current
snapshot reads no longer confuse “not reparsed” with “not present.” A destructive migration
downgrade is refused once any incremental run, lineage, dependency, or projection history exists.

## Bounded projections and assertion correctness

Every non-reuse operation emits one content-free `IndexProjectionEvent` in the same transaction as
its canonical file result and checkpoint. The event carries exact previous/current file-revision
IDs, affected semantic IDs, reverse-dependent topology fact IDs, assertion evidence IDs, and the
new semantic IDs requiring embedding. Reverse dependencies are resolved as a bounded transitive
closure with a hard cardinality limit.

The projection worker leases events durably. `SqliteIndexProjectionConsumer` constructs a canonical
semantic document from retained symbol metadata, calls the configured local embedding port only for
new symbol revisions, and appends model/revision-identified finite vectors. It invalidates only
superseded semantic vectors—not the vectors created by the same event—and records exact topology
fact invalidations. For registered assertion evidence in the same Brain/Project/Repository, it uses
the canonical graph evidence catalog with `source_invalidated`. That revocation atomically disputes
every assertion that no longer has sufficient current evidence. Delivery is acknowledged only after
all effects succeed; a crash leaves the event retryable, and every effect has an idempotent identity.

## HTTP contract

The deterministic Core OpenAPI includes:

- `POST /v1/indexing/runs` → `StartIndexRunCommand`, requiring a matching `Idempotency-Key`;
- `GET /v1/indexing/runs/{run_id}` → `GetIndexRunQuery`;
- `POST /v1/indexing/runs/{run_id}:cancel` → `CancelIndexRunCommand`, also idempotent.

All routes authenticate first and resolve an exact current Repository scope. Commit selectors are
lowercase hexadecimal Git prefixes. Strict request models reject unknown fields. Error bodies are
content-safe and never echo a repository path or input. The source-streaming/session composition is
kept outside this contract until PF-005 supplies the short-lived credential and mount boundary.
