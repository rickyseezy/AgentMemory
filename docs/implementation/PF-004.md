PF-004 keeps the coding host usable without hiding missing evidence. Independent recall channels run
concurrently under individual deadlines and one shared bulkhead. Every channel returns either a
successful result with its source freshness watermark or a typed degraded outcome. Authorization and
canonical-integrity failures remain fatal. Capture uses the existing owner-private encrypted spool
when Core is unavailable, and the existing recovery worker drains that spool idempotently when Core
returns.

## Architecture

The resilience bounded context follows Clean Architecture and is enforced by Import Linter:

- `resilience.domain` owns dependency/channel identities, circuit transitions, immutable execution
  policy, candidate/outcome values, and `DegradationPolicy`. It imports no framework, database,
  provider, or other product context.
- `resilience.domain.ports` defines the dependency-health repository, authorization, clock, and
  independent recall-source capabilities.
- `resilience.application` owns authorization-first structured concurrency, caller and channel
  deadlines, the semaphore bulkhead, circuit coordination, deterministic candidate merging, and
  cancellation cleanup.
- `resilience.infrastructure` supplies a concurrency-safe process-local health repository and the
  trusted system UTC clock. Circuit state is deliberately disposable control state: a restart closes
  circuits and permits a new bounded probe; it cannot grant authorization or make data canonical.
- The already shipped ingestion context owns capture durability and recovery. PF-004 narrows its host
  boundary further by enforcing one total hook deadline around direct append and fallback persistence.

The application depends only on domain ports. A channel adapter normalizes expected provider/store
failures to `RecallDependencyError`; it must not leak SDK exceptions, credentials, prompts, queries,
paths, or payloads. Composition supplies one adapter per channel and an immutable
`RecallExecutionPolicy`. Vendor names never appear in domain or application branching.

## Recall failure semantics

| Condition | Query behavior | Circuit behavior | Public evidence |
|---|---|---|---|
| Successful source | Include bounded candidates | Reset to closed | `available`, source freshness |
| Typed dependency failure | Preserve other channels | Count failure; open at threshold | `unavailable`, `AM_DEPENDENCY_UNAVAILABLE` |
| Channel/caller deadline | Preserve other channels | Count only a started timed-out call | `timed_out`, `AM_DEADLINE_EXCEEDED` |
| Open circuit | Skip source invocation | Remain open | `circuit_open`, `AM_CIRCUIT_OPEN` |
| Half-open recovery | Permit exactly one probe | Success closes; failure reopens | Probe outcome |
| Caller cancellation | Cancel and await all child tasks | Release a half-open probe without billing a failure | Cancellation propagates |
| Authorization failure | Cancel siblings and fail whole query | Do not convert to degradation | Fatal typed error |
| Canonical integrity failure or channel substitution | Cancel siblings and fail whole query | Do not convert to degradation | Fatal typed error |

`RecallQuery.requested_at` is evidence, not a trusted clock. Deadline and circuit decisions use the
injected `RecallClock`. An already-expired caller deadline skips the dependency and does not penalize
its circuit. A source is invoked at most once for one query; PF-004 performs no hidden retry and cannot
duplicate provider billing. Stable candidate IDs returned by multiple channels are merged by the
highest score and deterministically ordered by score then ID.

## Circuit and bulkhead invariants

`DependencyHealthRepository.acquire` makes the open-to-half-open transition under one lock, so only
one concurrent request receives the probe permit. Other requests immediately receive a typed open
outcome. The failure window resets after 30 seconds without another failure. A half-open failure opens
the circuit for a new interval; a half-open cancellation reopens it without incrementing the failure
counter. Thresholds and deadlines are bounded at composition and copied into an immutable mapping so
callers cannot mutate live policy.

The handler authorizes the complete scope before starting any channel. It creates one task per channel,
applies a per-source timeout inside the shared semaphore, and cancels and awaits siblings whenever the
parent or a fatal channel fails. This prevents orphan calls after the host request has ended.

## Capture durability and bounded host continuation

`AgentEventCaptureHook` validates and redacts before persistence. It first attempts the authenticated
loopback append for at most 35 ms. On an expected transport/dependency failure it writes the exact
canonical event to the AES-256-GCM SQLite spool. A 50 ms outer deadline covers both operations. The
hook therefore returns a bounded, content-free status even when a filesystem call stalls:

- `accepted`, `duplicate`, or `ignored` means Core returned a terminal result;
- `deferred` means the exact event is durably committed to the local spool;
- `spool_full` and `spool_unavailable` report bounded fallback failure; and
- `deadline_exceeded` reports exhaustion of the complete hook budget and never claims durability.

The spool uses an owner-only database and key, fresh AES-GCM nonces, authenticated metadata,
`synchronous=FULL`, bounded record/byte high-watermarks, and idempotency by event ID plus canonical
digest. It never evicts an unacknowledged event to admit a new one. The host continues on every status;
the adapter may surface a nonblocking diagnostic but must not turn capture degradation into task
failure.

Python's outer timeout cancels the awaiting task, but work already submitted through `to_thread` may
finish after the host returns. This is safe because the spool write is itself atomic and idempotent,
and the hook reports `deadline_exceeded` rather than falsely reporting `deferred` before commit.

## Recovery and duplicate safety

The launcher-supervised `SpoolRecoveryWorker` uses a renewable singleton lease and bounded batches.
It uploads canonical bytes in deterministic ordering-key order. Core returns a result for every event;
only `accepted` and `duplicate` are durable acknowledgements. The repository erases only each ordering
key's contiguous acknowledged prefix and atomically advances its watermark before releasing the lease.
Retryable, rejected, conflicting, missing, duplicated, or foreign response identities remain queued or
fail closed. A crash before acknowledgement retries the same event ID, and canonical append
idempotency converts the retry to `duplicate`, so recovery creates no duplicate effective state or
provider billing.

## Security and privacy

- Authorization occurs before channel tasks and is never represented as partial success.
- Canonical-integrity failures and adapter channel substitution fail the whole request.
- Failure evidence contains only closed channel, status, code, and UTC freshness fields.
- Circuit state contains no content and conveys no authorization.
- Capture results contain only event ID and closed status; no event payload or arbitrary exception is
  returned.
- Fallback encryption, owner-only paths, authenticated metadata, symlink refusal, bounded capacity,
  and durable acknowledgement are inherited from ADP-002/ADP-005 and remain covered by their suites.
