MEM-005 controls recall participation without rewriting the semantic status or correction history of
a memory. The lifecycle overlay is owned by the logical root memory, so every correction assertion
inherits the same archive, expiry, and forget decision.

## Architecture and state machine

`memory.domain.lifecycle` owns the closed `active`, `archived`, `expired`, and `forgotten` states,
the five transition actions, scope/time filtering, pin ranking, canonical transition plans, and
self-authenticating content-free receipts. It imports no database, HTTP, scheduler, or graph driver.

`memory.application.memory_lifecycle` exposes separate pin, archive, set-expiry, and forget commands
and handlers. Each handler performs an authorization-first read, validates the expected version and
deadline, then repeats authorization and complete-snapshot equality inside a serialized Unit of
Work. The injected-clock expiry scheduler uses the same state machine and persistence boundary and
emits `MemoryExpired` exactly when `expires_at <= now`.

The permitted transitions are:

- active/unpinned → active/pinned;
- active → archived;
- active or archived → the same state with a future expiry boundary;
- active or archived with a due boundary → expired; and
- active, archived, or expired → forgotten.

Forgotten is terminal. Pin is a ranking boost applied only after authorization, scope, lifecycle,
valid-time, and recorded-time eligibility. It cannot make an ineligible item visible.

## Persistence and deletion

One `BEGIN IMMEDIATE` transaction compares the complete lifecycle snapshot and appends the operation
receipt, guarded state transition, lifecycle event, graph projection source, durable outbox message,
and audit-chain entry. Forget additionally inserts the immediate-deny root tombstone, tombstones for
the root assertion and every correction assertion, an immutable deletion target set, a manifest,
and an authorized `governance.memory_deletion` job. Any failure rolls back all effects.

The deletion executor is idempotent and retry-safe across SQLite and Neo4j. It advances the manifest
through purging and verification, deletes every derived `ProjectionRecord` matching the manifest's
target set from local shadow generations and Neo4j graph/vector generations, verifies zero matches
remain, marks the manifest complete, and seals only its tombstones. Canonical receipts, audit facts,
and semantic history remain as governed evidence while all ordinary reads deny forgotten content.

PF-002 compares target type and hash against tombstones before every projection write and again at
generation validation. Consequently, retained canonical events cannot resurrect a forgotten root or
correction during repair, restart, or full rebuild.

## Authorization and interfaces

SQLite authorization requires the exact active owner principal, active Brain, current scope-covering
grant, and write-capable role. Missing, forgotten, tombstoned, expired-authority, wrong-actor,
wrong-grant, wrong-Brain, and out-of-scope targets collapse to the same not-found result.

The production composition root exposes:

- `POST /memories/{memory_id}:pin`;
- `POST /memories/{memory_id}:archive`;
- `POST /memories/{memory_id}:expiry`; and
- `DELETE /memories/{memory_id}` with the exact `forget-memory` confirmation.

Requests bind operation, actor, grant, Brain, correlation, causation, memory, expected version,
request time, deadline, and action-specific values into a request digest. Exact retries return the
stored receipt; divergent reuse conflicts. Response receipts contain no statement or evidence text.
