PRO-008 changes embedding providers or models without mixing incompatible vectors or overwriting the
active generation. It implements the state machine, canonical replay, dual-write routing, validation,
shadow readiness, explicit cutover, rollback, and governed retirement as separate responsibilities.
SQLite remains the only activation authority; Neo4j is a rebuildable physical projection.

## State and progress authority

`EmbeddingGenerationMigration` binds one Brain, source/target spaces, source/target generations, the
consistent source watermark, monotonic backfill/catch-up cursors, validation digest, rollback anchor,
retirement/deletion receipts, version, and timestamps. Its closed lifecycle is:

`Planned -> Building -> Backfilling -> DualWrite -> CatchingUp -> Validating -> Shadowing -> Ready`

Every nonterminal phase may become `Paused` or `Failed`. A pause persists its exact `resume_state` and
resumes only that state without changing progress. `Ready` cannot become active through an ordinary
transition: activation is a separate approved operation. `Active` may become `RolledBack`.

Domain constructors, SQLite checks, and immutable update triggers independently reject skipped phases,
cursor rewinds, incomplete backfills, premature validation, missing validation evidence, invalid
rollback anchors, mutable identities, and terminal-state rewrites. Every snapshot version has one
content-free evidence row. Crash recovery loads the last committed snapshot and replays only from its
cursor; provider writes must be idempotent under source-content and target-space identity.

## Canonical replay and live ingestion

`SqliteCanonicalEmbeddingContentSource` reads committed canonical `domain_events` by monotonically
increasing sequence. It returns only local `sqlite://domain-events/<uuid>` content references,
canonical payload digests, source identities, and closed classifications. It never reads or transforms
the source generation's vectors.

Planning captures the latest eligible sequence as `source_watermark`. Backfill reads only through that
fixed watermark. Immediately before dual-write, the worker captures a later catch-up watermark and
atomically publishes the source and target write route. It then replays the intervening canonical
records. Ingestion resolves the route as:

- source only before dual-write;
- source plus target while catching up, validating, shadowing, or ready;
- target only after cutover; and
- source only after rollback or validation failure.

The primary/secondary route is one SQLite row updated in the same transaction as the migration
snapshot and content-free cache-invalidation outbox event. Readers resolve one active generation by
Brain and canonical purpose through `active_embedding_generations`. Writers may resolve either the
original or newly active space identity without a routing gap.

## Independent activation gates

Structural validation runs before shadowing. Final evidence records canonical, target, covered,
missing, stale, duplicate, and privacy-violation counts; baseline/current quality; baseline/current
p95 latency; shadow samples and mismatches; and an external evidence digest. The production policy
requires all of these independent gates:

- exact 100% count and content coverage with no missing, stale, or duplicate records;
- zero privacy violations;
- no more than 0.04 quality regression on the integer-micro score;
- target p95 latency no more than 1.25 times baseline;
- at least 100 shadow samples; and
- zero shadow mismatches.

One favorable metric cannot compensate for another failed gate. Failure atomically removes the
secondary route, leaves the source active, and marks the target generation failed.

## Explicit cutover and rollback

The worker stops in `Ready`; it never cuts over by itself. `ActivateIndexGenerationCommand` requires:

- current owner/administrator authority revalidated in SQLite;
- `If-Match` naming the exact migration ID and Ready version;
- an `Idempotency-Key` matching the operation ID;
- an explicit approval ID naming a live Brain-wide owner/administrator grant; and
- the same principal and scope fingerprint used by the request.

One serial SQLite transaction verifies the Ready snapshot and approval, transitions target
`ShadowReady -> Active`, transitions source `Active -> RollbackReady`, switches the active read
pointer, removes dual-write, stores the immutable activation receipt, advances migration state, and
publishes a content-safe generation-change event. Exact retries replay the receipt. A changed
operation, approval, principal, scope, or expected version conflicts.

Rollback within the retained window performs the inverse pointer, route, and generation-state changes
atomically. The previous generation remains read-only for 35 days. Elapsed time alone never authorizes
deletion: the retention guard must additionally prove a verified recovery point contains the new
active pointer and that no active, rollback, route, or backup dependency still references the source.
Until OPS-004 supplies that proof, production retirement fails closed before canonical state or Neo4j
is changed.

## Physical cleanup

After canonical retirement, `Neo4jEmbeddingGenerationCleaner` derives the vector index and label only
from validated UUIDv7 bytes, drops that exact index if present, deletes only records carrying the exact
generation ID and label, and removes the matching generation metadata. Repeated cleanup is safe.
Canonical completion is recorded only after physical deletion succeeds, so a crash remains retryable.

## Clean Architecture and SOLID boundaries

- `providers.domain.migration` owns immutable states, progress, validation, policy, and retention
  invariants.
- `providers.domain.migration_ports` owns canonical source, target, inspection, persistence, routing,
  cleanup, retention, and identity capabilities.
- `providers.application.migration` owns planning, replay, pause/resume, validation, activation,
  rollback, and deletion orchestration.
- SQLite adapters own canonical persistence and replay reads.
- Neo4j owns only physical generation cleanup.
- `migration_http_api` translates strict authenticated transport contracts.
- `operations.bootstrap` is the production composition root.

Domain and application code import no FastAPI, SQLAlchemy, Neo4j driver, HTTP client, provider SDK, or
concrete adapter. Each infrastructure dependency implements a narrow port, and the activation
transaction remains independent of provider execution.

## Fail-closed dependency boundaries

Provider-backed re-embedding and shadow evaluation require PRO-009's per-operation egress
authorization and contained provider gateway. Core exposes the complete resumable control-plane
contract but binds `:run` to `ContainedEmbeddingMigrationRunner`, which returns a typed dependency
failure before resolving content, calling an adapter, or acquiring a network socket. PRO-009 must
replace that single port with the real migration target and inspector; no direct provider path is
allowed.

Source retirement similarly requires OPS-004 verified-backup evidence. Core binds the retention port
to `BackupBoundEmbeddingGenerationRetentionGuard`, which fails before retirement or physical
deletion until the backup subsystem can prove the required recovery point. These are dependency
sequencing invariants, not permissive placeholders.
