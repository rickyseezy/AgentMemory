## Outcome

ING-001 makes the local SQLite commit the only event acknowledgement authority. The application
encrypts the admitted canonical event, opens one serialized Unit of Work, ensures any referenced CAS
artifact, appends the event index and authenticated envelope, appends a checksum-bound local outbox
intent and audit fact, commits once under the enforced `synchronous=FULL`/WAL policy, and only then
returns `accepted`. No Neo4j, model, provider, filesystem projection, or worker result participates in
the ACK boundary.

An immediate process exit after the returned ACK leaves the event, envelope, artifact reference,
outbox intent, and audit fact durable. On Core restart, `DurableIngestionWorker` first releases expired
leases and scans committed events for missing dispatch intent. It then claims ready work in stable
priority, due-time, and UUIDv7 order. A verified message produces one immutable terminal
`event_projection_receipts` record and marks its outbox message completed in one transaction.

The receipt is the terminal ingestion projection: it proves that the acknowledged canonical record is
present, decryptable, schema-valid, index-consistent, artifact-bound, and ready for later idempotent
semantic consumers. It does not claim that future graph, memory, indexing, or provider projections
have run; those consumers remain governed by subsequent ING stories and ADR-002.

## Clean Architecture and repository boundaries

- `ingestion.domain.durable_processing` owns the closed processing dispositions, claimed-message
  lease value, verified terminal projection, and content-free worker result. It has no SQL, crypto,
  framework, operations-context, or host dependency.
- `ingestion.domain.ports` exposes distinct `AgentEventRepository`, `ArtifactRepository`,
  `OutboxRepository`, `IngestionAuditRepository`, `CanonicalEventProjectionVerifier`, and
  `DurableEventProcessingRepository` capabilities. The Unit of Work composes write repositories but
  remains the only commit authority.
- `AppendAgentEventHandler` orchestrates one use case. Repositories never commit and a duplicate
  returns only the previously committed acknowledgement evidence.
- `DurableEventProcessingHandler` claims, verifies, and transitions exactly one message. Integrity
  failures become terminal repair-required state; dependency failures release the lease for a due-time
  retry without fabricating success.
- `SqliteCanonicalEventProjectionVerifier` authenticates the outbox checksum and canonical JSON,
  envelope/AAD/key binding, AES-256-GCM ciphertext, strict AgentEvent schema, SQL event index,
  classification/scope/time/content hashes, and referenced artifact metadata before deriving a stable
  terminal digest.
- `SqliteDurableEventProcessingRepository` owns short lease, completion, retry, startup reconciliation,
  and repair-alert transactions behind the application ports.

The existing ingestion import-linter contracts continue to enforce adapter → application → domain
direction and forbid framework/context imports in domain and application code.

## Relational migration

Migration `0009_ing001_durable_processing` adds the required `artifacts` canonical metadata table and
`agent_events.payload_ref` foreign key. It expands `outbox_messages` with priority, due time, attempt,
lease, completion, safe error, and SHA-256 integrity columns; legacy messages receive deterministic
checksum and due-time backfills before the digest becomes non-null.

`event_projection_receipts` binds event, message, Brain, canonical hash, projection hash, and terminal
time. `ingestion_repair_alerts` stores only bounded safe codes/details and permits a null outbox
identity specifically when startup detects a committed event whose atomic dispatch intent is missing.
Dispatch and expired-lease indexes make startup and steady-state queries bounded and deterministic.

Downgrade is supported only while no ING-001 artifact, terminal receipt, repair alert, or non-legacy
outbox state exists. Once canonical ING-001 state exists, downgrade fails closed rather than deleting
durability evidence.

## Failure semantics

- Begin, artifact, event, outbox, audit, commit, simulated disk-full, or fsync failure raises a typed
  safe dependency error and no acknowledgement is constructed.
- A partial SQL write is rolled back with zero event, envelope, artifact, outbox, or acceptance-audit
  residue. Retrying the identical request is safe.
- A commit whose result is uncertain returns no ACK. If the commit actually reached durable storage,
  the retry resolves through the immutable event/content hashes as a duplicate.
- Process death after ACK is safe because the parent observes the result only after the FULL commit.
- Process death while leased is safe because startup returns an expired lease to ready; attempts are
  monotonic and no terminal receipt exists before its completion transaction.
- Outbox checksum, canonical JSON, ciphertext, envelope, index, or artifact divergence never produces
  a projection. It marks the message `repair_required`, opens one local repair alert, and appends a
  content-free `ingestion.repair_required` audit fact.
- A committed event missing its outbox intent is detected by the bounded startup reconciliation scan
  and receives an `outbox_missing` repair alert rather than being silently ignored.
