## Outcome

Every active memory now carries one immutable `MemoryProvenance` value. The value binds the
authorized actor, the creating agent, source task and terminal event, exact evidence IDs, extractor
and model revision, evidence watermark, extractor input, content hash, promotion policy, and its own
canonical provenance digest. `Memory.create` refuses activation when provenance is absent or when
content and provenance do not authenticate the same assertion.

`ExplainMemoryQuery` returns the stable memory ID, hierarchical scope, lifecycle state, content,
confidence dimensions, valid time, recorded time, actor/agent and extractor/model coordinates,
classification, retention, aggregate version, hashes, and evidence resolution. A caller supplies an
exact Brain, actor, grant, valid-time instant, and recorded-time instant. Starts are inclusive and
ends are exclusive; the response reports `effective` without hiding the historical record.

The installed launcher advertises `memory_explain` only when its authenticated Core client provides
the explanation capability. The read-only, idempotent, closed-world MCP tool requires the same six
coordinates as the HTTP contract, rechecks live Core readiness on every call, and proxies only to
the pinned literal-loopback endpoint. UUIDv7 values, canonical UTC instants, duplicate JSON keys,
unknown input fields, non-object responses, redirects, non-JSON content, and oversized responses
all fail closed. Core errors are reduced to public availability errors so protected local details
cannot cross the MCP boundary.

## Clean Architecture and SOLID boundaries

- `memory.domain.consolidation.MemoryProvenance` owns immutable creation and derivation invariants.
  `Memory` delegates provenance identity to that value instead of duplicating mutable fields.
- `memory.domain.explanation` owns the closed `available`, `purged`, and `missing` evidence states,
  exact evidence-lineage binding, and bitemporal evaluation.
- `memory.application.explain_memory` validates the query, uses an injected clock, and delegates one
  authorization-first request through the narrow `MemoryRepository` port.
- `SqliteMemoryRepository` is the outbound repository adapter. It performs authorization in the
  same SQL statement that selects the memory, then authenticates canonical JSON and every duplicate
  relational coordinate before constructing the aggregate.
- The FastAPI adapter translates strict UUIDv7 and canonical UTC query values into the use case and
  exposes no SQL, Cypher, filesystem, provider, or arbitrary evidence-read capability.
- The Go MCP adapter depends on the narrow `memoryExplanationClient` capability, publishes the
  complete closed response schema, and delegates authenticated transport to the literal-loopback
  Core client without importing persistence or graph concerns.

This preserves Dependency Inversion: domain and application code import no FastAPI, Pydantic,
SQLAlchemy, Neo4j, provider, identity, ingestion, operations, or retrieval implementation. Interface
Segregation keeps explanation reads separate from consolidation writes. The immutable value object
and `Memory.create` factory keep provenance validation in one Single-Responsibility location.

## Provenance identity

The actor is the principal whose currently active grant authorized consolidation. The agent is the
immutable local extractor identity that produced the untrusted candidate; it must equal the
extractor coordinate and cannot be `latest` or a display label. The extractor fingerprint binds its
implementation version, immutable model ID and revision, and output schema. The provenance document
also binds:

- the canonical terminal event that created the active memory;
- the exact sorted evidence IDs selected by deterministic promotion;
- the full task evidence watermark, including evidence the model did not select;
- the exact extractor input digest;
- the canonical content digest and promotion-policy version; and
- the source task identity.

The repository compares the canonical revision document against `memories`,
`memory_consolidations`, `memory_evidence`, and `event_task_lineage`. Any missing mandatory join,
noncanonical JSON, duplicate key, digest mismatch, model drift, actor drift, scope drift, or temporal
malformation is an integrity failure, never a partially populated explanation.

## Authorization and evidence resolution

The repository joins the requested memory to one exact active principal, Brain, and grant. Read is
allowed only for the closed owner/admin/editor/reader/auditor/worker roles and only when the grant's
project and repository cover the memory. An absent memory and a memory outside the caller's current
authority both return the same `AM_NOT_FOUND` response so existence is not disclosed.

Evidence is returned in the memory's canonical sorted order:

- `available` includes its immutable event ID, canonical envelope digest, event type, occurrence
  time, and the local `memory://evidence/{event_id}` resource coordinate;
- `purged` retains only the ID and digest when an authoritative AgentEvent deletion tombstone is
  active; and
- `missing` retains only the ID and digest when a damaged or incomplete store lacks the source.

Purged or missing evidence never inherits stale type, time, content, or resource metadata. The
explanation endpoint does not decrypt or return canonical event content; a later evidence-resource
query must independently authorize that content read.

## Canonical projection source and upgrade

Every activation transaction now writes a `MemoryProjected` domain event that is simultaneously a
PF-002 graph projection source. It has `projection_type=graph`, stable ID equal to the memory ID,
target type `memory`, SHA-256 target identity, canonical payload hash, and a source digest binding
content, terminal event, memory ID, and provenance digest. PF-002 therefore rebuilds Neo4j in an
isolated shadow generation from relational authority; Neo4j is never the provenance source of truth.

Migration `0016` validates every legacy MEM-001 provenance document against its consolidation row
before adding actor, agent, content, and extractor-input coordinates. It then rewrites legacy
`MemoryActivated` rows as fully hash-bound `MemoryProjected` sources and installs a database guard
against provenance updates. It refuses unsupported or divergent legacy bytes instead of inventing
metadata. Downgrade is allowed only when no memory revision exists because a populated downgrade
would discard the stronger canonical contract.
