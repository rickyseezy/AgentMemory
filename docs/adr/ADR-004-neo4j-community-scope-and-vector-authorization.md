# ADR-004: Neo4j Community cadence, multi-Brain scope, and vector authorization

- Status: Accepted
- Decision owners: Graph Owner and Security Owner
- Consulted owners: Retrieval, Providers, Operations, Release Engineering
- Decision date: 2026-07-13
- Review date: Monthly for Neo4j certification and 2026-10-13 for this decision
- Supersedes: None
- Related requirements: PRD Section 9; Technical Requirements Sections 2.1, 4.5-4.6, 11.6, and 11.12 SEC-001

## Context

AgentMemory needs temporal graph traversal and vector candidate filtering while remaining local and
using Neo4j Community. Database-per-Brain is operationally unsuitable in Community and cannot be
treated as authorization. Neo4j 2026.06/Cypher 25 is selected because filtered SEARCH must restrict
Brain/project/repository/classification before approximate ranking.

## Decision

### Version and support cadence

The initial BOM is Neo4j Community 2026.06.0 with queries explicitly targeting Cypher 25. Each
AgentMemory release pins one exact image platform digest; no tag or automatically updated container is
used. Release engineering evaluates each monthly Community release for vulnerabilities, license,
storage/index compatibility, query plans, vector semantics, migration, backup/rebuild, performance,
and rollback before its predecessor leaves AgentMemory's support window. Adoption occurs only in a
signed AgentMemory release. The first compatible 2026 LTS becomes the preferred line after the same
qualification; no in-place floating switch occurs.

AgentMemory supports the Neo4j image(s) bound to the AgentMemory versions in ADR-016's supported
window, not arbitrary vendor releases. One installation runs exactly the active release's image.

### One application database, explicit Brain scope

One local Neo4j service and one AgentMemory application database hold every local Brain. Every node,
relationship, projected edge, vector record, full-text record, cache key, migration, and integrity
finding carries `brain_id`. Database name, label, index, or connection credential is never used as the
Brain authorization boundary.

All stable labels have a composite uniqueness constraint on `(brain_id, id)` before writers activate.
EmbeddingSpace has a unique immutable fingerprint. Nodes also require `entity_type`, `schema_version`,
`classification`, `created_at`, and recorded-time fields. Assertions include valid/recorded intervals,
status, branch/commit scope, confidence components, and extractor identity.

Relationships that cross records include `brain_id` and are rejected unless both endpoints have the
same Brain. A governed cross-Brain transfer/reference remains two separately scoped assertions and
never enables traversal without separate authorization in each Brain.

### Query construction

Governance resolves a nonoptional `AuthorizedScope` before any graph call. It contains one Brain plus
explicit allowed project/repository IDs, classification ceiling, temporal scope, principal/grant/
policy versions, and action/purpose. Query ports accept this value object, not raw IDs or Cypher.

Cypher lives in reviewed versioned modules/files and is fully parameterized. User values may not form
labels, relationship types, property names, predicates, index names, or query text. Dynamic schema
names use only the closed UUID naming function in ADR-007. Every pattern applies Brain, narrower scope,
classification, status, generation, and temporal predicates inside the pattern/SEARCH, not after path
materialization. Results are authorized again before fusion and each expansion.

Graph requests have explicit depth/node/edge/time limits; defaults are depth 3, 500 nodes, 1,000 edges,
and 250 ms. An authorized explicit graph operation may request a validated bounded override, never an
unbounded `MATCH`.

### Assertion and projection ownership

Authoritative factual relations are reified Assertion nodes linked to subject/object/evidence. Direct
`CALLS`, `IMPORTS`, `CONSUMES`, `IMPLEMENTS`, `DEPENDS_ON`, `PRODUCES`, and `DEPLOYED_AS` edges are
derived acceleration and carry assertion ID, Brain, valid interval, branch/commit, and projection
generation. Orphan or mismatched edges are quarantined and excluded.

Graph writers consume canonical SQL outbox events under ADR-002. `MERGE` is used only with constrained
stable IDs; mutable name/path/text/URL is never a merge key. Neo4j contains no canonical event or grant
truth.

### Vector authorization and isolation

Each index generation has a dedicated `VectorRecord` label, vector property, and Cypher 25 SEARCH
index generated by ADR-007. Filterable properties include `brain_id`, `project_id`, `repository_id`,
`classification`, `status`, and `generation_id`. `SEARCH ... WHERE` applies these filters before
approximate candidate ranking. Post-filter-only authorization is prohibited.

One index has exactly one embedding space, dimension, dtype/quantization policy, normalization,
similarity, purpose, and generation. Quantization is disabled in the release correctness baseline. A
future supported mode creates a new space/generation and must pass golden comparison. Writes reject
wrong length, NaN/Infinity, incompatible metadata, content hash, Brain, or generation atomically.

SEARCH over-fetches within authorized filters because it is approximate. Requested/returned k,
generation, and filter fingerprint are recorded. Raw scores are compared only within one index query;
rank fusion combines separate spaces.

### Migrations and integrity

Ordered checksummed Cypher migrations are tracked canonically in SQLite with state, batch cursor,
counts, and errors. Create constraints/indexes before writers, backfill in bounded batches, validate
EXPLAIN plans/counts/scope/integrity, then activate the graph schema generation. Destructive changes
use shadow/rebuild/expand-contract. Integrity continuously checks required scope, evidence, direct-edge
authority, temporal ranges, vector generation, and orphan records.

## Security and privacy impact

Authorization before SEARCH/path generation prevents leakage via rank/count/timing better than
post-filtering. Separate Neo4j credentials allow only core graph operations; Neo4j has no host port,
browser, telemetry, or remote backup. It contains sensitive searchable derived data and therefore
requires host disk encryption under ADR-010. A compromised Neo4j cannot change canonical grants but may
expose its projection to a privileged local attacker, an accepted host-compromise residual risk.

## Compatibility, migration, and rollback

Query modules and migrations declare minimum/maximum graph schema and Neo4j/Cypher versions. AgentMemory
upgrade rehearses every supported prior release. A graph upgrade builds or migrates a new projection
generation; the prior generation remains rollback/rebuild input until validation and retention pass.
Failure discards target projection and restarts prior compatible image/generation or rebuilds. Neo4j is
never used to reconstruct missing canonical SQL state.

## Rejected alternatives

- Database per Brain: Community operations complexity and false authorization confidence.
- Post-filter vector authorization: unauthorized candidates can affect rank/timing and be exposed.
- Neo4j 5.26 LTS baseline: lacks the required certified Cypher 25 filtered SEARCH behavior.
- Direct LLM/user relationship names: schema/query injection and ungoverned facts.
- One mixed vector index: dimensions/model semantics are incompatible.
- Neo4j as canonical state: undermines SQLite ACK/rebuild boundary.

## Consequences

Every query is more verbose and schema/index count grows per vector generation. Exact scope predicates,
closed query modules, and rebuildable generations provide testable multi-Brain isolation in Community.

## Verification

- Constraint/migration tests on the exact pinned image and every supported upgrade source.
- Static Cypher scan and malicious ID/property/index fixtures prove no string-built query path.
- Generated role/scope/classification/time matrix, cross-Brain fuzzing, and timing/count canaries.
- Filtered SEARCH tests prove unauthorized records never enter candidate lists before ranking.
- Vector dimension/finite/order/generation/space isolation and approximate over-fetch tests.
- Inject orphan edges/assertions/vectors/temporal/scope corruption and verify quarantine/rebuild.
- Monthly performance/query-plan/golden-recall/backup-rebuild certification before BOM adoption.
