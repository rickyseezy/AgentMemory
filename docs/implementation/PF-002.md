PF-002 implements deterministic repair of graph, memory, search, code, and vector derived state. It
does not make Neo4j or a projection record canonical. A rebuild captures one committed SQLite
watermark, creates one immutable generation identity, replays only authorized canonical records at or
below that watermark, and changes query visibility through the SQLite active-generation pointer only
after every validation gate passes.

## Architecture and invariants

The implementation follows the existing Clean Architecture boundary:

- `operations.domain.projection_rebuild` owns the closed projection/state enums, manifest, replay
  records, canonical JSON, deterministic digest, idempotency key, and generation identity.
- `operations.domain.ports` owns capability-specific canonical-source, access/deletion-policy,
  shadow-generation, and rebuild-repository ports.
- `operations.application.commands.projection_rebuild` owns start, replay, checkpoint, validation,
  and activation orchestration. It imports no framework, SQL, Neo4j, or provider implementation.
- `SqliteProjectionRebuildAdapter` implements the canonical source, authorization/deletion checks,
  durable job repository, local shadow store, validation, audit, lease recovery, retry scheduling,
  and activation compare-and-swap.
- `Neo4jProjectionGenerationAdapter` writes Brain/type/generation-scoped graph and vector records with
  complete lineage. `ProjectionGenerationRouter` requires its count and digest to match the local
  generation before activation.
- `ProjectionRebuildWorker` drains queued work, contains job failures, converts provider/store
  outages to typed partial results, and recovers only expired building leases.

The normative idempotency key is the SHA-256 of length-framed projection type, Brain ID, immutable
source watermark, and implementation fingerprint. The shadow generation ID additionally binds the
complete manifest digest. The manifest pins application build, relational and graph schema heads,
parser, extractor, every provider/model revision, embedding space, and implementation fingerprint.

Stable IDs are unique within Brain, projection family, and generation. An exact duplicate is accepted
without increasing the effective count; a divergent duplicate fails with an integrity violation. A
generation digest sorts records by stable ID and binds content and source digests, so page order and
retry boundaries cannot change the result.

## Durable lifecycle

The closed state path is:

`queued -> building -> validating -> ready -> active`

`building -> partial -> building` is the only resume path. Invalid state changes fail closed. A failed
generation is quarantined and never query-visible. A ready generation activates only when the active
pointer still equals the value captured when the rebuild was created; otherwise it becomes
`superseded`. Therefore two concurrent shadow builds cannot overwrite one another or expose a mixed
generation.

Every projection record contains Brain, projection type, generation, stable ID, canonical source event
and sequence, source/content digests, HMAC-compatible target hash, canonical payload, manifest digest,
schema version, and creation time. Neo4j receives the same lineage. SQL remains the sole active-pointer
authority, so activation is one atomic local transaction even though shadow construction spans stores.

## Authorization, deletion, and privacy

- Start and every replay record reauthorize the exact actor/grant/Brain against current canonical
  principal, Brain, and grant validity. Activation reauthorizes once more.
- The authoritative tombstone table is checked immediately before every write. Validation also joins
  the completed generation against current tombstones; a newly committed deletion blocks activation.
- Missing artifacts and unavailable dependencies produce a bounded safe reason and retain the last
  committed cursor. The implementation never generates replacement text or vectors.
- API responses, errors, worker results, and audit facts contain only operation metadata, counts,
  digests, states, timestamps, and closed reason codes. They never return payloads, vectors, paths,
  queries, prompts, or arbitrary exceptions.
- Lifecycle transitions append idempotent hash-chained `projection.rebuild.*` audit events in the same
  SQLite transaction as the corresponding state change.

## Validation and rollback

Activation requires:

1. replay cursor equals the immutable source watermark;
2. repository effective count equals the validated record count;
3. every record resolves to its exact canonical event lineage;
4. source, content, manifest, and generation digests match;
5. all stored payloads remain canonical valid JSON;
6. no current tombstone matches a projected target;
7. Neo4j graph/vector count and deterministic digest match SQLite; and
8. the projection-specific golden-query gate passes.

Old generations remain isolated after activation. Rollback is performed by starting a rebuild with the
previous pinned manifest and desired committed watermark. It produces a new immutable generation and
uses the same validation and compare-and-swap path; operators never edit an active pointer or revive a
failed generation manually. See [the PF-002 runbook](../runbooks/PF-002-PROJECTION-REBUILD.md).

## Verification evidence

The acceptance suite covers deterministic identity/digest, state-machine transitions, duplicate
idempotency, real SQLite migrations, real repository replay, tombstone non-resurrection, revoked access
checks, missing-artifact resume, expired worker leases, provider outage, Neo4j Brain/generation scope,
relational/graph digest agreement, concurrent activation compare-and-swap, old/new generation
isolation, authenticated REST/OpenAPI, worker failure containment, and hash-chained audit persistence.

The load test replays 10,000 canonical records with 4,096-record bounded pages and a 30-second release
ceiling. Release benchmarking must retain the exact machine/OS/runtime/corpus cohort and compare at
least five independent trials according to ADR-014; the unit/load ceiling is a regression tripwire,
not a substitute for signed release qualification.

80.00% mutation score. `tools/check_python_mutation.py` independently rejects missing, malformed,
