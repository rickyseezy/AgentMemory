ADP-004 provides a usable, vendor-neutral integration for an agent process that has no native
lifecycle API. It observes only what the local wrapper can actually see: process boundaries and
exit status, stdout/stderr transcript bytes, privacy-authorized filesystem deltas, Git state changes,
and explicit checkpoints. It never converts a transcript role into prompt, turn, tool, or hidden
reasoning provenance.

## Clean Architecture and SOLID boundaries

- `ingestion.domain.generic_adapter` owns transcript source ranges, explicit unknown provenance,
  candidate causal associations, filesystem/Git/process evidence, stable evidence identities, and
  canonical privacy-safe payloads.
- `ingestion.domain.ports.AgentAdapterPort` is the vendor-neutral durable-capture boundary.
  `TranscriptDecoder`, `SensitiveTextRedactor`, `WorkspaceObserver`, `GitObserver`, and
  `ProcessExecutor` are capability-specific ports rather than one generic infrastructure service.
- `ingestion.application.generic_adapter` owns transcript import, event translation, workspace/Git
  diffing, process-wrapper orchestration, explicit checkpointing, and the MCP tool contract.
- `generic_transcript`, `generic_observers`, and `generic_http` are replaceable outer adapters. They
  contain format, filesystem, process, Git, and HTTP details; application/domain code imports none of
  those frameworks.
- `generic_cli` is the composition root. It reads one launcher-written owner-only context document,
  reads the 32-byte session credential through the protected-file boundary, registers the immutable
  manifest idempotently, and selects wrap, transcript-import, checkpoint, or MCP stdio mode.
- `generic_mcp` is an inbound adapter for the explicit checkpoint use case. It does not access
  SQLite, Neo4j, credentials, or HTTP directly.

The generic capability manifest declares session, process/command, file, Git, and transcript
evidence as `inferred`; task checkpoints as `explicit_tool_only`; and prompt content, turn lifecycle,
tool lifecycle, and every other unavailable signal as `unsupported`. The existing ADP-003 admission
policy enforces that matrix by exact adapter version, binary digest, manifest digest, event family,
and capture method.

## Stable transcript identity and idempotency

The transcript source digest is SHA-256 over the exact original bytes before decoding or redaction.
Each record retains its original byte start/end offsets. The normative chunk digest is a
length-framed SHA-256 over:

1. `agentmemory-transcript-chunk-v1`;
2. canonical session UUIDv7;
3. observable source channel (`import`, `stdout`, or `stderr`);
4. source SHA-256;
5. byte start; and
6. byte end.

That digest maps deterministically to a canonical RFC 9562 UUIDv7-shaped event ID. Reimporting the
same bytes in the same session with the same selected format/encoding therefore reaches the
canonical event ledger with the same event IDs. Exact retries return `duplicate`; divergent content
cannot reuse the identity because the source digest changes, and identical text in another session
cannot collide. A record without a source timestamp uses the stable session UUIDv7 time for direct
imports; wrapper output uses the observed process-completion time. Missing correlation/ordering
configuration deterministically falls back to the session ID, so later imports cannot change the
canonical envelope. The channel discriminator prevents identical stdout/stderr bytes from collapsing
into one event.

The strict decoder supports plain text, JSON Lines, and JSON arrays in explicit UTF-8, UTF-8 BOM,
UTF-16 LE BOM, or UTF-16 BE BOM encodings. It never guesses. Invalid bytes, a BOM mismatch, duplicate
JSON keys at the MCP boundary, malformed structured records, non-UTC timestamps, unsupported roles,
oversized records, and prohibited hidden-reasoning fields fail before event creation.

## Privacy and evidence honesty

- Secret assignments, bearer tokens, OpenAI-style keys, GitHub tokens, AWS access-key identifiers,
  and launcher-configured private expressions are redacted before `AgentEventData` exists.
- The raw transcript is never stored by the importer. Only a one-way source digest, stable offsets,
  redacted text, source completion, and explicit source role are included.
- Every transcript/checkpoint payload contains `prompt_provenance=unknown`,
  `turn_provenance=unknown`, and `tool_provenance=unknown`. Canonical payload validation continues to
  reject chain-of-thought, scratchpad, private-reasoning, and equivalent fields recursively.
- Process evidence stores the executable basename, argv digest, stdout/stderr digests, exit code,
  timing, and completion status. It does not persist argv, environment variables, stdin, or raw
  output outside redacted transcript events.
- Observer relationships carry only `kind=candidate`, `basis=session_time_window`, session ID, and
  UTC window. The domain rejects an authoritative causal association.

## Filesystem, Git, process, and MCP behavior

`LocalFileObserver` resolves exactly the selected workspace, never follows symlinks, opens regular
files with no-follow semantics where supported, and applies private/ignore policy before opening
bytes. Default exclusions cover `.git`, `.agentmemory`, environment files, key/PEM/SSH names, and
credential/secret paths. `.agentmemoryignore` adds UTF-8 glob rules; negation is deliberately refused
because an additive policy cannot widen access. File count and size bounds fail safely.

The workspace diff produces deterministic add/change/delete evidence and recognizes a rename only
when one deleted path and one added path share a unique digest. Ambiguous duplicate-content moves are
reported as deletion/addition instead of fabricated rename causation.

`SubprocessGitObserver` uses fixed `git -C ...` argv calls, a bounded sanitized environment, no shell,
a five-second deadline, and bounded UTF-8 output. It observes commit, branch/detached state, and a
hashed checkout fingerprint. A non-Git directory returns no Git evidence.

`ArgvProcessExecutor` calls `create_subprocess_exec` and cannot interpret shell syntax. It supports
bounded stdin, inherited interactive stdin, live tee of stdout/stderr, bounded capture, timeout,
graceful termination, kill fallback, and explicit `complete`/`abrupt` classification. The wrapper
captures inferred session start/completion, redacted stdout/stderr transcript chunks, file/Git
changes, and a content-free command result through one `AgentAdapterPort`.

The stdio MCP server follows the latest stable protocol available at implementation time,
`2025-11-25`. It performs initialize/initialized negotiation, exposes only tools capability, supports
ping, lists exactly `agentmemory_checkpoint`, validates exact arguments before side effects, returns
structured accepted/duplicate receipts, reports tool execution failures inside `CallToolResult`,
writes JSON-RPC frames only to stdout, and terminates cleanly on EOF. Frames are newline-terminated,
duplicate-key rejecting, and limited to 64 KiB. The later product-wide MCP epic can compose the same
handler and tool schema without changing its application logic.

Checkpoint IDs are canonical client-generated UUIDv7 values. Their embedded UTC millisecond is the
checkpoint occurrence time, and the same ID must be reused for an exact retry. This makes the MCP
tool's idempotency promise byte-for-byte true without persisting mutable retry state in the stdio
adapter; reusing an ID with a different summary remains a conflicting-event security failure.
