## Outcome

MEM-006 turns the host-neutral continuity path from ADP-006 into a complete multi-source session
briefing. A request reads task/checkpoint events, current long-term memories, current Checkout revisions,
and independently governed procedures through separate ports. It returns recent constraints, blockers,
unresolved work, decisions, failures, validations, changes, and supporting facts with explicit
freshness, revision compatibility, evidence identity, producer provenance, and deterministic rank.

The implementation remains agent-neutral. Claude Code, Codex, Gemini CLI, Cursor-compatible hosts, and
generic MCP consumers execute the same application handler and selection policy. Host adapters only
clamp the caller's budget, supply platform capabilities, and render the typed result. Producer host,
model, adapter, capture method, and source session remain source facts and are never rewritten as the
consumer identity.

## Clean Architecture and SOLID boundaries

- `retrieval.domain.continuity` owns briefing categories, freshness and revision states, atomic items,
  code coordinates, query/budget/result values, content-free selections, and the authenticated
  `ContextInjectedEvent`. It imports no SQL, HTTP, cryptography, host SDK, or provider implementation.
- `retrieval.domain.ports` separates `TaskReadRepository`, `MemoryQueryRepository`,
  `CodeRevisionQuery`, `RetrievalPipeline` behavior, `ProcedureReadRepository`, and
  `ContextInjectionRepository`. A source or persistence technology can change without changing policy.
- `retrieval.application.start_session_briefing` concurrently invokes the bounded sources, defensively
  rechecks every returned item against the immutable `AuthorizedScope`, applies the pure deterministic
  policy, then persists the content-free event before returning context.
- `SqliteContinuityReadRepository` remains the task/event adapter.
  `SqliteMemoryBriefingRepository`, `SqliteCodeRevisionQuery`, and
  `SqliteContextInjectionRepository` implement the new capabilities without leaking SQL into the
  application layer.
- `operations.bootstrap` is the composition root. Domain and application code never branch on agent
  vendor or database implementation.

These boundaries preserve dependency inversion, interface segregation, single responsibility, and
Open/Closed behavior. The retrieval import-linter contracts enforce layer direction in CI.

## Deterministic selection policy

The handler requests at most 200 candidates per bounded source. Every repository must prefilter by
Brain, principal, active grant, project, repository, Checkout, classification, and temporal scope;
the application repeats scope, classification, and temporal checks before policy execution.

The initial category priority is:

1. safety constraints;
2. blockers and unresolved work;
3. decisions;
4. failures;
5. validations;
6. changes; and
7. supporting facts.

Equal-priority candidates sort by occurrence time descending and stable item ID. Duplicate
category/content atoms collapse before selection. The selector then applies category, project, and
known source-session diversity. No category, project, or known session consumes more than half of the
selected items while a fitting eligible alternative exists; priority remains the deterministic
tie-breaker.

The default budget is 1,200 tokens, 12 items, and 20 KiB. Selection reserves 64 tokens and 512 bytes
for the envelope, uses the conservative one-token-per-three-UTF-8-byte counter, and measures the exact
canonical item representation. Items and procedures are indivisible. An oversized item is skipped;
it is never sliced. Procedures are considered only after memory selection and therefore cannot evict
or reveal a memory.

The policy is deterministic across source ordering, retries, and consumer hosts. If no semantic item
survives authorization and policy, the result is explicit `no_answer`; an empty injection event is
still persisted.

## Freshness and revision compatibility

- Items at most 30 days old are `current`.
- Items older than 30 and at most 180 days are `stale`.
- Items older than 180 days are excluded as `stale_beyond_horizon`, except safety constraints, which
  remain visible and stale.
- The latest authorized Checkout observation is matched by Checkout ID, or by repository only when
  that repository has exactly one current scoped Checkout.
- A historical branch different from the current branch is `branch_incompatible`. Blockers,
  unresolved work, failures, validations, and changes are excluded with that reason. Decisions,
  constraints, and supporting knowledge may remain visible with the incompatibility label because
  they can remain useful outside one branch. Unknown branch coordinates remain explicitly `unknown`.

## Authorization, deletion, and integrity

The HTTP adapter authenticates before scope resolution. Task, memory, and revision SQL queries require
an active Brain, active principal, current grant, and exact explicit scope before exposing candidates.
Memory reads require an active lifecycle row, a non-expired valid/recorded interval, an allowed memory
class, current revision, and immutable evidence. A revoked grant therefore hides memory immediately.

Before event persistence, `SqliteContextInjectionRepository` reauthorizes the complete scope in the
same transaction. If authorization changed after the reads, no receipt or event is written and no
briefing is returned. Malformed persisted memory JSON, evidence, timestamps, identities, or digests
fail with typed integrity errors rather than partial fabricated context. Errors contain no memory
content, path, SQL, credential, or arbitrary exception text.

## Content-free event and retry contract

Every completed selection, including `no_answer`, creates a SHA-256-authenticated
`ContextInjectedEvent`. Its canonical JSON contains only event/operation/Brain/principal identities,
scope and request digests, selected item and semantic IDs, categories, ranks, evidence event IDs,
budget/usage, status, policy version, and time. It contains no copied semantic content, prompt, hidden
reasoning, vector, or credential. The domain rejects a forged or all-zero event digest.

The operation ID is the idempotency identity. An exact retry compares the request digest, canonical
selection, budget, usage, status, policy, scope, and time, then returns the first persisted event ID
even if the retry generated another candidate UUIDv7. Divergent reuse returns `AM_CONFLICT`. Event and
receipt insertion is atomic. The receipt and its `ContextInjected` event are immutable; the migration
does not impose that new restriction on older event families with documented mutable recovery fields.

## Migration and rollback

Migration `0020_mem006_session_briefing` adds the immutable receipt table, digest/JSON/usage/status
constraints, lookup index, receipt update/delete guards, and `ContextInjected` event guards. It is
reversible while no briefing evidence exists. Once evidence exists, downgrade refuses rather than
silently deleting audit and idempotency state. Follow
[the MEM-006 runbook](../runbooks/MEM-006-SESSION-BRIEFING.md) for diagnosis and rollback.
