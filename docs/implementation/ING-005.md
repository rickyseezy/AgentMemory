## Outcome

Every daemon capture now crosses one ordered privacy boundary after adapter authority/scope admission
and before canonical encoding, envelope encryption, event persistence, outbox enqueue, or provider
invocation. A policy can exclude content, deterministically sanitize it, or retain it as encrypted
`local_only` material. The caller receives `ignored` for a policy exclusion and treats that result as
terminal, so excluded material is neither persisted nor repeatedly spooled.

The default policy is deliberately offline and restrictive. It excludes common secret files anywhere
in a repository, removes explicit private blocks, detects secret formats and sensitive JSON fields,
classifies PII/secrets, redacts deterministic spans, and denies egress whenever content remains tainted
or no exact destination route exists.

## Clean Architecture and SOLID boundaries

- `ingestion.domain.privacy` owns immutable policy revisions, closed classifications/actions/stages,
  exact destination facts, deterministic policy/stage digests, and invariant-checked outcomes. It has
  no SQL, HTTP, filesystem, provider SDK, FastAPI, or composition dependency.
- `ingestion.application.privacy` owns the ordered `CapturePolicyPipeline` and the final
  `SanitizedProviderEgressHandler`. Both depend only on narrow policy and provider ports.
- `CapturePolicyRepository`, `CapturePolicyDecisionRepository`, and `ProviderEgressInvoker` apply
  Interface Segregation and Dependency Inversion. A scanner cannot open a socket and a provider
  adapter cannot decide its own authorization.
- `SqliteCapturePolicyRepository` and the two SQLite decision repositories are outbound adapters.
  Policy activation and standalone exclusions use serialized transactions; accepted-event evidence
  participates in the existing AgentEvent Unit of Work.
- `CaptureAgentEventHandler` orchestrates authority, payload reading, privacy evaluation, replacement
  with sanitized bytes/classification, and durable append. The composition root selects concrete
  repositories; inbound HTTP, MCP, generic-agent, and host-hook adapters only translate terminal
  content-free receipts.

These boundaries preserve Repository Pattern, Single Responsibility, Open/Closed provider extension,
and testable dependency inversion. New scanners or policy stores can be added behind the existing
contracts without changing transport or event persistence.

## Immutable policy model

`CapturePolicy` is a complete, bounded, canonical revision. It records Brain/repository scope, policy
identity/version, ignore patterns, private marker pairs, permitted media types, secret and PII
actions, minimum classification, exact egress routes, and hard resource limits. Canonical JSON and a
SHA-256 fingerprint make evaluation replayable without relying on ambient defaults.

Resolution order is exact repository scope, then Brain scope, then secure default. A requested
historical version must exist exactly. Activation appends only the next revision, supersedes rather
than edits prior rules, and is idempotent only for identical canonical bytes. Repository policy can
only narrow Brain policy: add exclusions/private markers, reduce media types/routes/limits, increase
classification, or change handling from redaction to local-only/exclusion.

An egress destination contains provider ID, exact public HTTPS origin on port 443, region, immutable
model ID, and purpose. Credentials, URL paths/query/fragment, IP literals, local/private names, unsafe
classifications, duplicate routes, and unapproved destinations are invalid before evaluation.

## Ordered privacy pipeline

The pipeline always executes these six recorded stages in order:

1. **Exclusion** validates portable relative paths and applies ignore precedence before decoding.
   Hidden reasoning is unconditionally excluded.
2. **Decode** rejects empty/oversized input, prohibited media, archives, tar signatures, binary
   controls, UTF-32, malformed UTF-8/UTF-16, duplicate JSON keys, and excessive JSON depth. Accepted
   text becomes one deterministic Unicode/JSON representation.
3. **Classification** raises declared/policy classification for private blocks, secrets, contact PII,
   government IDs, and payment cards. Local-only actions dominate every lower class.
4. **Secret scan** checks common provider/cloud/private-key/bearer/assignment formats, sensitive JSON
   field names, email/phone/government/card patterns, percent/HTML encoding, nested standard Base64,
   and nested Base64url. Finding count is hard bounded.
5. **Redaction** replaces complete private blocks and findings with closed stable tokens, then emits
   canonical UTF-8 JSON or normalized UTF-8 text. No finding value is included in evidence.
6. **Egress decision** denies exclusions, local-only content, any sensitive taint, restricted class,
   absent destinations, and route mismatches. Only an exact clean policy route returns `allow`.

The input is required as a mutable bounded `bytearray`; it is overwritten in `finally` on success,
exclusion, or failure. Temporary decode copies remain process-local and are released after the call.
The returned object contains sanitized bytes or no bytes, classifications/dispositions, input/output
digests, content-free detector locations/counts, exact policy identity/digest, and a digest of all six
stage decisions.

## Atomic persistence and local-only storage

For sanitized or local-only events, policy evaluation replaces the untrusted event payload before the
canonical encoder runs. The existing per-event random AES-256-GCM envelope then protects the canonical
event. Local-only action deliberately retains the original sensitive value only inside this encrypted
envelope, raises classification to `local_only`, and records unconditional egress denial.

On a new accepted event, `privacy_decisions`, `agent_events`, `agent_event_envelopes`, outbox, and
append audit commit in one `BEGIN IMMEDIATE` transaction. A privacy-receipt failure rolls back every
write and cannot produce an ACK. Duplicate capture returns existing immutable history. Conflicting
event identity remains a conflict.

For an exclusion, the handler writes only a standalone content-free decision: actor/scope IDs, policy
and stage digests, input digest, closed findings counts, classification/disposition/egress/reason, and
time. It writes no event, envelope, artifact, outbox item, append audit, payload, source value, secret,
or arbitrary diagnostic. Exact retry is idempotent; changed evidence under the same event identity is
a conflict.

## Pre-provider enforcement

`SanitizedProviderEgressHandler` is the only application boundary intended to acquire a
socket-owning remote provider adapter. It evaluates the same pipeline with the exact destination and
stable downstream idempotency key. Denial raises a content-free `IngestionEgressDeniedError` before
the provider port is called; allow passes only the returned sanitized bytes. Provider-specific
network enforcement remains additive and cannot weaken this application decision.

## Migration and rollback

Migration `0013_ing005_capture_privacy` creates strict `capture_policy_versions` and
`privacy_decisions` tables. Database constraints enforce immutable scope/version uniqueness, one
active revision per scope, closed state/classification/egress/disposition values, exact digest sizes,
valid JSON evidence, and one decision per subject. Downgrade is refused while either policy history or
privacy evidence exists because deleting it would make historical processing unverifiable.
