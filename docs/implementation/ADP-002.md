| Field | Value |
|---|---|
| Story | ADP-002 — Capture without slowing the host |

| IPC | `POST /v1/agent-events:append` on authenticated loopback Core |

ADP-002 turns the admitted ADP-001 envelope into a fast durable queue item. No host-specific behavior
enters the use case: Codex, Claude, Gemini, GLM, generic shell wrappers, and future adapters call the
same contract. The hook ends after strict validation/redaction and either a durable Core acknowledgement
or a durable encrypted local-spool acknowledgement. Parsing code, calling a model/provider, embedding,
reranking, extraction, Neo4j traversal, graph mutation, and memory enrichment are absent from this path.

## Clean Architecture flow

1. `AgentEventCaptureHook` applies the injected redactor, parses the shared strict AgentEvent schema,
   canonicalizes it, and calls an injected `LocalIpcClient` under a 35 ms default IPC deadline.
2. `HttpAgentEventIpcClient` accepts only the fixed HTTP loopback append route, uses one injected
   `httpx.AsyncClient` connection pool across calls, sends the protected bearer capability, and accepts
   only the closed `accepted`/`duplicate` result.
3. The Core router authenticates before parsing, caps the request at 96 KiB, rejects duplicate/non-strict
   JSON through the ADP-001 boundary, and returns content-free RFC-style status data.
4. `CaptureAgentEventHandler` resolves the exact active daemon-owned adapter manifest, runs ADP-001
   admission and authoritative scope resolution, then invokes `AppendAgentEventHandler`.
5. The command encodes through `AgentEventEncoder`, encrypts through
   `AgentEventEnvelopeEncryptor`, and opens an `AgentEventUnitOfWork`. Domain/application layers import
   no FastAPI, Pydantic, SQLAlchemy, HTTP, cryptography, operations, identity, or provider implementation.
6. One `BEGIN IMMEDIATE` transaction inserts the event index, encrypted canonical envelope, one
   content-free outbox message, and one hash-chained audit fact. `synchronous=FULL` is connection policy.
   The handler commits only a new accepted item and returns only after commit succeeds. An exact retry
   returns `duplicate`; event-ID reuse with different payload/canonical digest or ordering-key/sequence
   reuse is a conflict. A disk/commit error never becomes an acknowledgement.

Repository contracts remain capability-specific and transaction-scoped. The SQLite adapter is the only
owner of SQL; cryptographic construction is isolated behind an encryption port; host transport and spool
are replaceable adapters. Constructor injection and immutable values keep the flow SOLID and testable.

## Storage and encryption

Migration `0007_adp002_durable_capture` expands the canonical classification constraint and creates:

- `agent_adapter_manifests`: immutable active/revoked descriptor authority (registration is completed by
  ADP-003; capture already fails closed when no exact manifest exists);
- `brain_encryption_keys`: one random 256-bit BKEK per Brain, stored only as AES-GCM ciphertext under the
  protected installation root key with key/version/purpose AAD; and
- `agent_event_envelopes`: authoritative resolved scope, ordering/correlation metadata, canonical digest,
  clock skew, random per-event DEK ID, payload nonce/ciphertext, and wrapped-DEK envelope.

Each event receives a new random 256-bit DEK and two independent random 96-bit nonces. The DEK encrypts
the complete canonical event; the Brain BKEK encrypts the DEK. Scope, event ID, classification, algorithm,
version, and key IDs are authenticated as canonical AAD. Ciphertext includes the full 128-bit tag.
Keys are never stored plaintext in SQLite or returned/logged. The installation root key is read from the
existing protected-file adapter for the minimum operation and best-effort zeroed. Authentication/tamper
failures are translated into safe integrity/dependency failures without returning plaintext.

The query index contains only the bounded metadata required to route later enrichment. The outbox body
contains Brain ID, event ID, event type, and schema version—never prompt/file/tool payload. Its topic is
`am.local.<brain-id>.ingestion.agent-event-appended.v1`, and its message key is the canonical ordering key.

## Bounded encrypted spool

When IPC times out or is temporarily unavailable, the host writes the exact redacted canonical bytes to
an owner-only SQLite spool using a separate protected 256-bit spool key and a fresh random 96-bit nonce.
The database enforces `synchronous=FULL`, WAL, foreign keys, secure deletion, a 10 ms busy deadline,
unique event IDs, and unique non-null ordering coordinates. Defaults are 10,000 records and 64 MiB;
operators cannot configure unbounded storage. A batch returns at most 100 items, ordered by ordering key,
then sequence/insertion order, while preserving every original event ID. Only explicit accepted/duplicate
IDs are deleted. Exact retries must match both authenticated identity metadata and the canonical content
digest, including when conflicting content has the same byte length. ADP-005 owns automated
reconciliation/watermarks; ADP-002 supplies its durable primitive.

Expected hook statuses are `accepted`, `duplicate`, `deferred`, `spool_full`, `spool_unavailable`, and
`invalid`. They contain at most event ID and status. A timeout never waits for enrichment or reports
captured content.

## Performance profile and verification

The published developer profile is Apple Silicon macOS, CPython 3.14.6, local APFS storage, SQLite WAL
with `synchronous=FULL`, protected-file key access, AES-256-GCM event/DEK encryption, and one local Core
process. On 2026-07-20, 500 sequential unique real encrypted appends measured p50 3.898 ms, p95 5.727 ms,
p99 7.871 ms, and maximum 16.304 ms. The release test repeats 100 real appends and fails at p95 >= 50 ms.
The isolated healthy hook profile measured p95 0.109 ms across 1,000 samples.

Mandatory tests cover the real latency bound, cold spool initialization, concurrent hooks, short timeout,
capacity, ordering, idempotency, ciphertext/AAD tamper, wrong Brain/key, invalid adapter/scope, atomic
event/outbox/audit persistence, conflicting IDs/order, duplicate retry, strict HTTP boundary, content-free
errors, and an actual spawned Core process that exits with `os._exit(0)` immediately after sending its
accepted acknowledgement; a fresh parent connection verifies event and outbox durability.

Focused ADP-002 qualification on 2026-07-20 passed 33 tests. The full Python suite passed 695 tests at
90.58% combined line/branch coverage; package and changed-code line/branch gates each exceeded 80%.
The complete critical mutation campaign includes every configured critical line and passed at 82.37%
(556/675). Ruff formatting/lint, Mypy, Pyright, all 11 Clean Architecture contracts, Bandit, pip-audit,
deterministic schema/OpenAPI export, locked distribution build, Go race/coverage gates, and the embedded
UI's 45 tests with 91.44% statement and 84.21% branch coverage also passed. Hosted supported-platform and
Docker certification remain release-pipeline responsibilities; absence of those artifacts must fail the
overall product release even though the ADP-002 story implementation is complete.
