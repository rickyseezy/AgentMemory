# ID-004 — Select and enforce retrieval scope

Status: implemented and qualified

## Production design

`ResolveRetrievalScopeHandler` resolves authorization before any graph or retrieval port is
called. It returns a frozen `AuthorizedScope` containing exactly one Brain, explicit Project,
Repository, and optional Checkout IDs, classification and temporal ceilings, action, purpose,
role, grant revision, policy version, and installation security epoch. The canonical scope
fingerprint and internal cache key change whenever any security-relevant dimension changes.

The role policy permits Owner, Admin, Editor, and Reader recall. Global recall additionally
requires Owner or Admin and an explicit Project list. Auditor, Adapter, and Worker are denied.
Current scope requires exact Project and Repository IDs; related scope starts from that exact
binding, boosts it deterministically, and expands only through active evidence-backed repository
topology. Selected and global modes never interpret an omitted list as “all.”

## Clean Architecture mapping

| Layer | Implementation |
|---|---|
| Domain | `identity/domain/retrieval_scope.py` |
| Application | `identity/application/queries/resolve_retrieval_scope.py` |
| Outbound adapters | `sqlite_retrieval_scope.py` |
| Inbound adapter | `POST /v1/retrieval-scopes:resolve` |
| Composition | `operations/bootstrap.py` |
| Relational schema | `0006_id004_retrieval_scope` |

The application owns the authorization and graph protocols. SQLite is replaceable and cannot
flow into the domain or application layers. The graph adapter receives the already-authorized
Project allowlist and intersects it in SQL before traversal, then the handler intersects the
result again before constructing the scope.

## Persistence and cache invalidation

Migration `0006` expands `scope_grants` to the seven closed roles, optional Project/Repository
narrowing, validity bounds, and a monotonic version. The authorization snapshot also binds the
Brain policy version and installation security epoch. Revocation or grant mutation makes the old
grant unusable and changes the aggregate grant revision and cache key. Downgrade refuses when it
would invalidate scoped roles or canonical grant references.
