## Architecture and responsibility boundaries

IDX-004 follows the existing Clean Architecture boundaries. The indexing domain defines immutable
candidate batches, exact source coordinates, matching rules, qualifications, and decisions. The
application layer owns extraction registration and linking orchestration through repository,
assertion, lineage, and plugin ports. Inbound HTTP and outbound SQLite/graph/parser implementations
remain adapters; they do not change domain policy.

Each parser returns one complete `ApiTopologyCandidateBatch` for one immutable source-revision
context. An empty batch is meaningful: it supersedes the prior output for that source and removes
those candidates from the current matching universe without deleting history. Raw source bytes are
bounded to 8 MiB, exist only in `ApiTopologySourceArtifact`, and are never written to topology
tables.

## Supported topology evidence

The pinned production registry has non-overlapping owners for:

- OpenAPI JSON/YAML REST contracts and operations;
- GraphQL schemas and named operations;
- Protocol Buffer service/RPC declarations and generated gRPC symbols;
- common source server routes, `axios`, `fetch`, GraphQL operations, and generated gRPC calls.

Plugins emit `EndpointCandidate`, `ClientCallCandidate`, `ContractBindingCandidate`, and
`ServiceOwnershipCandidate`. Every candidate carries Brain, Project, Repository, source file,
source-revision context, semantic entity, evidence ID, relative path, classification, and observed
time. Registration verifies those values against the canonical IDX-001, GRA-002, and IDX-003 rows.
Environment data is retained only as a normalized reference such as `USER_API_URL`; values and
secrets are not accepted by the domain model.

## Deterministic linking and qualification

`ApiTopologyLinkPolicy` evaluates the complete authorized latest-candidate universe with this fixed
precedence:

1. canonical contract operation ID;
2. generated-client symbol;
3. configured service/base-URL ownership, including normalized gateway prefixes;
4. normalized transport operation and route template.

A unique strongest, non-dynamic match is `confirmed`. Equal-strength matches, dynamic routes, or
otherwise unresolved alternatives remain ranked `qualified` candidates and never silently become
authoritative. Each result retains rule/version, confidence basis points, qualification codes,
supporting candidate IDs, and exact client/server/supporting evidence IDs.

The graph adapter proposes every qualified `CONSUMES` candidate. It activates only confirmed
matches that pass canonical GRA-002 evidence, authorization, temporal, and confidence policies.
`CONSUMES` is the intentionally governed cross-project predicate: all evidence must share the Brain
and classification, the assertion's client scope must be evidenced, and the operation scope must
authorize every involved repository. Other predicates retain the same-scope evidence rule.

## Durability, replay, and staleness

Candidate batches, link operations, matches, and assertion receipts are append-only and protected
by update/delete triggers. Operation IDs and canonical digests provide exact replay; reuse with
different input is a conflict. Matching reads only latest batches at the requested time from
explicitly authorized repositories.

Every candidate registers a semantic-to-evidence dependency. Every produced assertion registers
client and server source-revision lineage through IDX-003. A changed or deleted semantic therefore
enters the existing branch-aware invalidation pipeline, while historical topology batches and link
decisions remain auditable. The migration can downgrade only while all IDX-004 tables are empty.

## Local API

- `POST /v1/indexing/api-topology/extractions` authenticates, resolves current repository authority,
  decodes bounded base64 source in memory, selects exactly one plugin, and returns a content-free
  batch receipt.
- `POST /v1/indexing/api-topology/links` authenticates, resolves an explicit selected-project scope,
  links one client candidate, and returns the complete ranked explanation path.

Both mutations require an `Idempotency-Key` equal to `operation_id`. The routes are included in the
production composition root and deterministic OpenAPI export.

coverage is 88.16%; the `agentmemory` package has 89.42% line and 82.61% branch coverage; changed
production code has 90.15% line and 80.53% branch coverage. The complete critical-domain mutation
campaign killed 6,349 of 7,923 mutants for an 80.13% score, with no untested, timed-out, suspicious,
or ignored results.
