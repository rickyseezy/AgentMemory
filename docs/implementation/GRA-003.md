## Outcome

GRA-003 turns each currently authoritative assertion into a bounded, directly traversable Neo4j
relationship without making Neo4j authoritative. Every edge carries its assertion and revision IDs,
canonical lifecycle event, exact Brain/project/repository/Checkout scope, classification, valid and
recorded intervals, aggregate version, generation, content fingerprint, and deterministic projection
digest. Retrieval returns the assertion/revision/event coordinates needed to explain why the edge may
be followed.

The feature is agent-neutral. Assertion events produced from Codex, Claude, Gemini, GLM, generic MCP
hosts, or future adapters enter the same canonical SQLite ledger and the same projection workers.
Caller text never becomes Cypher, a relationship type, a database name, or an authorization scope.

## Clean Architecture boundaries

- `graph.domain.materialized_edges` owns the predicate registry, generation-specific edge identity,
  lifecycle representation, projection digest, traversal explanation, durable work values, and
  deterministic integrity policy.
- `graph.domain.materialized_edge_ports` separates canonical reads, graph projection, durable work,
  current authorization, active-generation resolution, integrity scope discovery, and append-only
  integrity evidence.
- `graph.application.materialized_edges` owns materialization, reverse validation/repair, and bounded
  traversal use cases. `graph.application.materialized_edge_worker` owns retry, lease, polling, and
  failure-containment policy.
- `graph.adapters.outbound.sqlite_materialized_edges` implements canonical source, current
  reauthorization, durable work repository, generation resolver, scan-scope source, and immutable
  finding/repair journal.
- `graph.adapters.outbound.neo4j_materialized_edges` implements parameterized generation-scoped
  direct-edge projection, quarantine, inspection, and traversal.
- `operations.bootstrap` composes both workers from ports and starts/stops them with Core lifespan.

Domain and application modules import no SQLAlchemy, Neo4j, FastAPI, host, or provider SDK. All store
access is capability-scoped and repository-backed. The design preserves single responsibility,
interface segregation, dependency inversion, and closed predicate/relationship extension points.

## Canonical event and durable work transaction

`SqliteAssertionRepository` inserts an `AssertionActivated` or `AssertionDisputed` domain event and
its `assertion_edge_projection_jobs` row in the same `BEGIN IMMEDIATE` transaction as the assertion
lifecycle revision. A committed lifecycle event therefore cannot be lost between the canonical
ledger and the projection queue. Exact assertion-command retries do not create a second job because
the source event ID is the queue primary key.

Each job binds source event, assertion, Brain, principal, original scope fingerprint, project,
repository, optional Checkout, classification, aggregate version, event type/digest, creation time,
and schema. A trigger prevents those fields from changing. Only the closed operational state may
move through `ready -> leased -> ready|completed|quarantined`.

Claims use a serialized SQLite compare-and-swap, deterministic ordering, a bounded lease, and a
maximum of twelve attempts. Expired leases below the limit return to `ready`; exhausted leases become
quarantined. Retry delay is exponential and capped at five minutes. Completion verifies the exact
owner/lease/attempt tuple, appends one immutable projection receipt, and changes the job to completed
in one transaction. Receipts bind generation, projection digest, status, aggregate version, and time.
Exception messages, Cypher, source content, vectors, paths, prompts, and credentials are never stored.

## Fresh authorization and stale-event safety

The worker does not trust the original scope snapshot. Before every attempt,
`SqliteMaterializedEdgeAuthorization` verifies that:

- the exact job binding is still leased to that worker attempt;
- principal and Brain remain active;
- project, repository, optional Checkout, and their canonical binding remain active;
- at least one current owner/admin/editor/reader grant covers the exact coordinates; and
- grant, policy, and security epochs can be sealed into a new `AuthorizedScope`.

Authorization loss quarantines the job without exposing whether an inaccessible assertion exists.
The canonical source then validates the trigger event but deliberately reloads the newest lifecycle
revision in one SQLite read snapshot. A delayed activation event arriving after a dispute therefore
projects the version-2 retirement, never the stale version-1 edge. A missing graph generation or
temporarily absent endpoint is retryable; malformed lineage, a divergent same-version edge, or a
revoked scope fails closed.

## Projection identity, idempotency, and generation isolation

`PredicateRegistry` exhaustively maps the seven `AssertionPredicate` values to the seven reviewed
`GraphRelationshipType` values. The adapter uses Cypher 25 dynamic relationship types only with the
mapped enum value and passes all identities, scopes, documents, limits, and classifications as
parameters.

The relationship `id` is a deterministic UUIDv7-shaped value derived from assertion ID and generation.
`assertion_id` remains the canonical authority pointer. This satisfies the existing per-type
`(brain_id,id)` uniqueness constraints while allowing old and new PF-002 generations to coexist.
`MERGE` keys use Brain plus that generation-specific ID. Retirement and quarantine additionally match
the exact assertion and generation, so no operation can mutate another generation.

Aggregate versions are monotonic. Version 1 creates or idempotently verifies an active edge. Version
2 updates only the matching edge to `retired`; if activation was never materialized, retirement is a
safe no-op. An older activation cannot overwrite a retirement. A same-version divergent retry is a
conflict unless the integrity capability explicitly performs a governed repair.

All materialized edges also carry the base GRA-001 relationship fields (`created_at`, `revision_id`,
relationship type, endpoints, scope, classification, schema, temporal interval, fingerprint), so the
global Neo4j readiness scan continues to validate them. The graph migration adds a composite range
index for each supported relationship type across Brain, assertion, generation, projection status,
and quarantine state.

## Reverse integrity, quarantine, and repair

The periodic integrity worker obtains at most 100 active Brain/generation pairs per scan. SQLite
selects a deterministic current owner/admin/editor principal and builds only the projects and
repositories covered by active grants. The worker compares canonical assertion expectations with all
managed projected edges in that exact scope and generation.

The policy reports:

- `missing` when a current active assertion has no retrieval-visible edge;
- `orphan` when a retrieval-visible managed edge has no canonical assertion; and
- `mismatch` when lineage, scope, relationship type, lifecycle, digest, or duplicate effective state
  differs from the expected edge.

Finding IDs bind generation, kind, assertion, and expected/actual digests and deliberately exclude
detection time, making repeated scans idempotent. Findings are appended before mutation. Orphans are
quarantined. Mismatches quarantine every matching assertion edge in that generation, then reproject
the one canonical expected edge; this leaves a forged duplicate quarantined while restoring the
correct edge. Missing edges are reprojected. A repair receipt is appended only after the graph action
succeeds. Already-quarantined orphans remain excluded and do not generate endless duplicate findings.

Ordinary traversal always filters exact Brain, authorized projects/repositories/Checkouts,
classification ceiling, active generation, `projection_status='active'`, `quarantined=false`, and an
open recorded interval. Results are bounded to 1,000 and contain no arbitrary properties.
