PF-003 adds one vendor-neutral admission layer over the already production-owned agent and provider
ports. It does not import extension code into Core and it does not add a vendor switch. An adapter is
selected only by immutable adapter ID, declared `agent` or `provider` kind, negotiated protocol, and
approved capabilities.

## Clean Architecture and SOLID boundaries

- `extensions.domain.models` owns the immutable manifest, closed kind/capability/permission enums,
  protocol range, live probe evidence, authorization request, registration, canonical digests, and
  highest-mutual-version negotiation.
- `extensions.domain.ports` owns narrow authorization, package-signature, permission, challenge,
  clock, live-transport, repository, audit, outbox, identity, and Unit of Work ports.
- `extensions.application.register_adapter` owns the only registration orchestration. Its order is
  current authorization, exact idempotency replay, immutable-version check, package trust,
  permission approval, negotiation, live probe, aggregate creation, repository/audit/outbox stage,
  and atomic commit.
- `extensions.adapters` translates HTTP, SQLite, signature policy, live probe transport, and runtime
  composition. The domain and application import no framework, database, graph, HTTP client, agent,
  provider, or operations context. Import Linter enforces those dependencies.
- `ExternalAdapterRuntimeRegistry` returns the existing `AgentAdapterPort` or `ProviderAdapterPort`
  based only on declared kind. Structural conformance and duplicate identity are rejected before an
  implementation is made resolvable.

This separation follows Open/Closed and Dependency Inversion: adding a conforming adapter changes a
signed manifest and composition data, not identity, ingestion, memory, graph, indexing, retrieval, or
learning packages. Agent and provider implementations remain Liskov-substitutable behind their
existing ports.

## Admission and trust invariants

The manifest binds schema version, adapter ID and semantic version, kind, executable/OCI package
SHA-256, signature-object SHA-256, signer identity, minimum and maximum protocol, capabilities, and
requested permissions. Collections are sorted, unique, non-empty, and kind-specific. Agent adapters
must capture canonical AgentEvents; provider adapters must implement embedding. Mutable versions,
mixed agent/provider authority, undeclared capabilities, unknown permissions, duplicate JSON fields,
unknown JSON fields, and unsupported protocol ranges fail before runtime execution.

`DigestBoundAdapterPackageTrust` checks the publisher allowlist before delegating exact
package/signature/publisher coordinates to the release-owned signature verifier. Providers use the
PRO-002 offline Sigstore bridge; signed agent packages use the PF-001 release/package verifier. The
permission policy defaults to only `canonical_event.write` for agents and `provider.execute` for
providers. Workspace, transcript, provider-gateway, or other expanded authority must be enabled
explicitly by installation policy.

The live probe sends an unpredictable bounded challenge plus the exact manifest, package, protocol,
kind, and capabilities. The response must contain exactly seven fields, echo all security identities,
report `passed`, and arrive with an independently observed runtime digest equal to the signed package.
Duplicate keys, unknown keys, missing/extra capabilities, altered challenge, protocol or digest,
oversized output, transport failure, and stale-shaped evidence are rejected. Probe evidence is
self-digested and registration revalidates its binding.

## Persistence, authorization, and events

Every request is bearer-authenticated at the HTTP boundary and reauthorized against the current
principal, grant, Brain status, validity interval, and owner/admin role before any registry candidate
read. SQLite records are Brain-scoped. A registration contains no package bytes, credentials,
transcripts, prompts, paths, vectors, or arbitrary process errors.

`SqliteAdapterRegistrationUnitOfWork` uses the existing serialized `BEGIN IMMEDIATE` writer and
atomically commits:

1. one immutable registration aggregate;
2. one operation/request-digest receipt;
3. one content-free canonical `adapter.registration.activated.v1` domain event;
4. one ready outbox message; and
5. one hash-chained audit fact with exact actor and Brain lineage.

An exact operation replay performs current authorization but no trust, probe, audit, or duplicate
effective write. A new operation for the same exact immutable version adds only its operation receipt.
Conflicting operation reuse or same-version package drift fails. Registration and operation evidence
is trigger-protected against update/delete, and downgrade is refused once evidence exists.

## Public SDK and conformance

The dependency-free Python and Go SDKs contain no Core internals. Both expose the same kind,
capability, permission, challenge, and response vocabulary. The Go reference adapter is a separate
program using four-byte big-endian framing and bounded strict JSON. It is built and exercised as an
external-language conformance implementation. PRO-002's Python and Go OCI provider references cover
the provider side of the same substitution rule.

See [the public SDK guide](../integrations/PUBLIC-ADAPTER-SDK.md) for authoring and
[the operator runbook](../runbooks/PF-003-ADAPTER-EXTENSIONS.md) for registration and incident steps.
