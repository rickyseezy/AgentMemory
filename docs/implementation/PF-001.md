# PF-001 implementation record

| Field | Value |
|---|---|
| Story | PF-001 — Install the complete local Brain from one MCP installation |
| Delivery status | In progress |
| Release status | Not releasable |
| Current slice | Installer domain/application kernel, portable operation repository, and Linux durable journal |

## Scope of this slice

This slice establishes the smallest executable boundary on which the complete installer can
be built safely:

- the closed, ordered PF-001 install-phase state machine;
- immutable transition evidence, retry, idempotency, and resume rules;
- the `InstallApplication` saga with one narrow port per required phase;
- durable save-before-side-effect and save-after-transition orchestration;
- application-layer journal contracts with typed errors;
- a Linux owner-only, atomic, integrity-protected filesystem journal;
- a strict, versioned journal-backed operation repository that authenticates and
  domain-validates every restored snapshot;
- deterministic unit, decision-table, recovery, tamper, and fuzz tests;
- launcher lint, architecture, race, and coverage gates.

It intentionally contains no fake Docker success path and no placeholder that can report the
product as Ready. A production composition must remain impossible until every required Ensure
phase has a real adapter and its acceptance evidence.

## Acceptance status

| PF-001 acceptance area | Status after this slice |
|---|---|
| Pristine host automatically provisions a certified local container runtime | Not implemented |
| Signed AgentMemory release, images, models, SBOM, and provenance are verified | Not implemented |
| Compose, SQLite, Neo4j, and local model services reach verified readiness | Not implemented |
| Install resumes safely after kill, network loss, power loss, logout, or reboot | Domain, application, and Linux journal foundation only |
| Repeated installation returns `AlreadyReady` without duplicate resources | Domain and application contract only; no resource adapters exist |
| Agent configuration is preserved and merged atomically | Not implemented |
| Offline installation passes the same trust and readiness gates | Not implemented |
| Certified macOS, Windows, and Linux end-to-end matrices pass | Not implemented |

The current filesystem journal is implemented only for Linux. macOS requires a dedicated
extended-ACL ownership check because mode bits alone do not prove owner-only access. Windows
requires DACL ownership checks, an atomic `ReplaceFileW` path, and directory/durable flush
handling. Generic Go filesystem behavior is not treated as equivalent proof on either OS.

PF-001 must not be moved to Done until every acceptance criterion and mandatory test in the
technical requirements is executable and passing. In particular, this slice does not yet
include the required mutation runner, signed resource inventory, installation lock adapter,
installation-key reference adapter, setup/status surface, runtime provisioners, release and
model verification, Compose stack, agent configuration adapters, macOS/Windows journals,
offline path, or certified-host end-to-end suites.

## Architecture decision gate

Section 13 of the technical requirements requires ADR-001 through ADR-018 before implementation
begins. That entry gate has not been met, so this branch is explicitly an experimental,
unreleasable foundation and is not yet specification-compliant implementation. It cannot waive
or reinterpret that MUST. The decisions most directly governing PF-001 are ADR-001, ADR-016,
ADR-017, and ADR-018, but all 18 are required. Before this work can enter a production delivery
line, the complete ADR set must be approved and this slice must be revalidated or refactored
against it. Nothing here selects a runtime vendor flow, signing policy, Compose topology,
privilege model, or destructive recovery behavior on behalf of those ADRs.

## Red-Green-Refactor record

- **Red:** decision-table tests first described the normative 14-phase order, rejected skipped
  and contradictory transitions, replay/resume rules, save-before-side-effect behavior, all
  interrupted phase boundaries, reboot receipt binding, journal contract, crash checkpoints,
  and strict snapshot restoration. The initial packages or required types did not exist, so
  these contracts failed to compile or failed their assertions.
- **Green:** the minimum inward domain values/aggregate, named application ports and saga,
  journal contract, Linux filesystem journal, and operation repository were added to
  satisfy those contracts. No runtime or Docker adapter was introduced to manufacture a Ready
  result.
- **Refactor:** phase behavior was kept behind named interfaces, persisted DTOs were separated
  from domain types, repeated validation was centralized in constructors/restoration, public
  errors were reduced to stable privacy-safe codes, and first-party architecture/coverage
  checks were extracted into tested tools.

The executable evidence is in the colocated `*_test.go` files. This record covers only the
current slice; each later PF-001 implementation increment requires its own Red-Green-Refactor
entry and mandatory test evidence.

## Security and privacy impact

- Positive controls in this slice are owner-only journal paths, no-symlink/regular-file and
  invoking-owner checks, HMAC-SHA-256 entry chaining, full-document authentication, atomic
  replacement with parent-directory synchronization, bounded payload/history sizes, strict
  DTO restoration, plan/evidence binding, privacy-safe public errors, and rejection of
  obvious secret-bearing evidence fields.
- The application and domain layers cannot import host filesystem, process, network,
  persistence, ambient entropy, or Docker capabilities under the checked standard-library
  allowlist and inward dependency rules.
- This slice does not process source code, Brain data, provider credentials, or telemetry and
  does not perform network or Docker operations.
- Release-blocking gaps remain: the operation-key source, machine/OS-principal binding,
  protected monotonic sequence anchor, signed release/resource inventory, production lock,
  Darwin extended-ACL adapter, Windows DACL/durable-replace implementation, canonical UUIDv7
  generator, and fixed digest-encoded per-operation journal locator do not exist. Raw operation
  IDs must never be concatenated into a path. An older otherwise valid journal is therefore not
  yet protected against rollback. The current adapter must not be composed into a distributable
  installer until those controls and their attack tests pass.

## Compatibility, migration, and rollback

- The module and CI toolchain are pinned to Go 1.26.5. Portable domain, application, and
  repository contracts compile on the currently targeted OS/architectures, while the concrete
  journal is deliberately build-tagged only for Linux.
- `operation_snapshot` and journal formats are explicit versioned DTOs. Unknown versions or
  fields fail closed; no implicit migration is attempted. A future version must add a tested,
  signed, forward-only migration or preserve the previous reader for rollback.
- This branch has no production composition root and performs no user-machine mutation, so
  source rollback is removal/revert of this isolated slice. Once a real installer writes a
  journal or host resource, rollback must follow the signed release-generation and ownership
  rules in ADR-016 through ADR-018; deleting or rewriting a user journal is not an acceptable
  recovery strategy.
