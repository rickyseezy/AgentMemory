# ID-001 implementation record

| Field | Value |
|---|---|
| Story | ID-001 — Resolve stable project identity |
| Delivery status | Repository implementation complete |

| Governing decision | ADR-006 |

ID-001 resolves an existing workspace identity through the fixed precedence `manifest -> checkout
registry -> repository fingerprint -> approved heuristic`. It never manufactures a Repository from a
path, name, or content resemblance. A tier with multiple distinct authorized candidates returns
`ambiguous` and the candidates; it never silently selects or merges them.

## Clean Architecture and SOLID boundaries

- `identity.domain` owns UUIDv7 identities, versioned keyed fingerprints, immutable observations,
  outcomes, remote normalization, and the pure `IdentityResolutionPolicy`.
- `identity.application` owns `ResolveWorkspaceHandler`. Authorization is executed before host
  observation or persistence lookup. The handler depends only on capability-specific Protocol ports.
- In-process MCP bridges use `ManifestReader`, `DeviceIdentityPort`, and `VcsIdentityPort`. The Core
  HTTP boundary accepts the equivalent already-observed keyed evidence, not a raw host/container path.
- `identity.adapters.outbound` supplies no-follow manifest reading, argv-only Git observation,
  installation-keyed HMAC fingerprinting, launcher-provisioned device evidence, and static-query
  SQLite repositories.
- `identity.adapters.inbound` supplies the strict FastAPI router, canonical error mapping, and
  content-free response DTOs. The operations composition root is the only context that wires it.
- Import Linter enforces identity infrastructure -> adapters -> application -> domain and forbids
  framework, SQL, provider, and operations imports from domain/application.

Every dependency has one narrow reason to change. Resolution policy is storage-independent, host
observation is independent of persistence, and every adapter can be replaced behind its port.

## Identity and privacy invariants

- Project, Repository, Checkout, and Device have separate canonical UUIDv7 IDs.
- `GitRepositoryFingerprintV1` binds VCS/object format, sorted full root object IDs, optional stable
  repository ID, and an HMACed normalized primary remote. It excludes path, branch, HEAD, and dirty
  state.
- Remote normalization removes credentials, query, fragment, default port, trailing slash, and
  `.git`; it canonicalizes SSH aliases and rejects local/ambiguous paths.
- Checkout evidence separately binds Repository, Device, volume, path, and worktree fingerprints.
  The canonical path is only a keyed mutable location lookup.
- Root-only Git similarity without a normalized remote or explicit stable Repository ID is
  candidate-only and never enters automatic Repository lookup. An unverified/changed Device cannot
  enter Checkout or heuristic merge; manifest or portable Repository evidence may still resolve the
  Project without silently adopting that Checkout.
- Raw machine IDs, paths, and remotes are never persisted or returned by the resolver. The HTTP body
  accepts only already-keyed host evidence and strict manifest UUIDs, and its response emits only
  authorized entity IDs, status, source, candidates, and closed explanation codes.
- A copied known manifest with incompatible repository evidence raises `AM_CONFLICT`. Authorization
  or revocation is evaluated before candidates are queried.

## Persistence and migration

Migration `0003_id001_workspace_identity` creates Devices, Projects, Repositories, versioned
Repository fingerprint aliases, Project-Repository links, Checkouts, and approved Checkout aliases.
All lookup indexes are Brain-scoped, exact, version-aware, and status-aware. Foreign keys prevent
orphan mappings; checks bound fingerprint widths and closed states. Repository adapters use static
parameterized SQL, and bounded Repository-ID sets cross the SQL boundary as JSON data rather than
interpolated syntax.

The migration is forward/backward tested from the preceding PF-002 head. Fingerprint algorithm
upgrades add aliases alongside existing entity IDs; they never rewrite canonical identity.

## TDD and verification evidence

The red phase first proved the missing `identity` package. The green/refactor sequence then added the
pure precedence policy, strict values, capability ports, host adapters, real SQLite repositories,
path-free HTTP contract, composition, and architectural enforcement.

The acceptance corpus covers:

- all four precedence tiers, exact explanations, duplicate candidates, not-found, and ambiguous fork;
- authorization-before-observation and immediate grant revocation;
- Git and non-Git directories, same-name separation, path moves, and real Git repository continuity;
- HTTPS/HTTP/SSH/scp normalization, credentials, query/fragment, ports, malformed/local paths;
- strict manifest schema, traversal, duplicate roots, unknown fields, oversize files, and symlinks;
- keyed Device/volume/path isolation and absence of raw host evidence;
- real migrated SQLite resolution, Brain scoping, conflicts, approved heuristics, and dependency errors;
- authenticated path-free HTTP success/error/privacy contracts and deterministic public OpenAPI; and
- Clean Architecture, Ruff, Mypy, Pyright, full repository regression, line/branch coverage, and
  critical-policy mutation gates.
