PRO-010 adds a local, provider-neutral observability authority. It does not call a pricing web
service, upload telemetry, or store provider response bodies. Administrators publish immutable,
content-addressed pricing and finite budget versions. Provider execution reserves estimated cost
atomically before dispatch, records one canonical bounded outcome against the exact pricing version,
and reconciles actual cost once. Operators receive Brain-scoped health and status aggregates without
content, vectors, credentials, paths, arbitrary error text, or unbounded metric labels.

## Clean Architecture and repository boundaries

- `providers.domain.observability` owns pricing, budget admission, operation facts, drift
  comparisons, and status values. The domain imports no SQL, HTTP, FastAPI, provider SDK, or Docker
  implementation.
- `providers.domain.observability_ports` defines administration, pricing, budget, drift scheduling,
  probe, and status repositories.
- `providers.application.observability` owns authorization, pricing selection, reserve-before-
  dispatch, actual-cost reconciliation, immediate drift execution, status queries, and the scheduled
  worker.
- `SqliteProviderObservabilityRepository` is the sole canonical persistence adapter.
- `BudgetedTelemetryProviderBatchGateway` decorates a provider batch gateway. It resolves the exact
  effective `PricingSnapshot`, serializes a budget reservation, refuses queue/degrade outcomes
  before the wrapped gateway, validates the returned batch outcome, and records/reconciles telemetry.
- `ProviderSchedulerWorker` converts budget queue/degrade decisions into durable content-free release
  reasons. A queued decision receives a retry time; degradation is terminal for the vector channel
  so exact/lexical/graph fallback can proceed.

The billable provider scheduler remains fail-closed until its protected payload and result-CAS
adapters are composed. There is therefore no unguarded production dispatch path. That future
composition must wrap its provider gateway with `BudgetedTelemetryProviderBatchGateway`; direct
composition is an architecture violation.

## Pricing and budget consistency

Pricing is administrator supplied, versioned, immutable, content-addressed, profile-version bound,
operation bound, currency bound, and effective for a finite half-open time interval. Cost arithmetic
uses integer micro-units and ceiling division; adapter code contains no hardcoded provider prices.

Budget policies are finite and versioned. Each policy chooses exactly one exhaustion behavior:

- `queue`: provider work is durably released with `budget_queued` and a retry time;
- `degrade`: vector work is not dispatched and the exact configured subset of `exact`, `lexical`,
  and `graph` channels is returned as the permitted fallback.

`BEGIN IMMEDIATE` plus the process write lock serializes reservation races. The persisted reservation
contains the exact pricing snapshot, request digest, decision, reserved amount, and degradation
channels, so an idempotent replay cannot change behavior. Actual usage releases the reservation and
increments spent cost in the same transaction as the immutable operation fact. If actual cost
exceeds the estimate or period limit, the overrun is visible through an alert and zero-clamped
remaining balance; it is never discarded.

## Drift detection and write suspension

The canary corpus is the shipped, public, content-addressed PRO-003 corpus. Registration rejects any
other corpus identity or item order. The baseline contains only:

- exact profile/version, capability attestation, embedding space, and generation;
- model-revision, corpus, and quantized-vector fingerprints;
- ordered content digests, quantized vector norms, distance ordering, tolerances, and schedule.

The runtime source re-resolves the active profile, generation purpose, capability attestation, and
model revision before every probe. Local Qwen uses the authenticated internal embedding sidecar.
Remote built-ins use a new short-lived PRO-009 permit bound to the active capability-attested policy
route; the request is distinguished from draft profile activation by its exact `drift-probe`
operation identity.

`ProviderVectorDriftProbe` validates count, order, finite numeric shape, dimension, and nonzero norms.
It reduces vectors to a quantized fingerprint, integer norms, and distance ordering, then overwrites
every mutable vector buffer in `finally`. Its representation and errors never contain vector
values. The evaluator checks authority coordinates, revision fingerprint, vector fingerprint,
per-vector norm tolerance, and bounded ordering inversions.

A mismatch atomically appends the observation and alert, creates an immutable generation write
suspension, and advances the canary schedule. SQLite guards reject new document-vector work for that
generation even if an application check is bypassed. The scheduling repository also checks the
suspension before insertion and returns the stable `drift_suspended` problem. Suspensions cannot be
updated or deleted: recovery requires a new embedding space/generation and the PRO-008 migration
flow.

## Status and privacy

`GET /v1/providers/status` is restricted to owner, administrator, or auditor authority and returns:

- profile health and open/half-open/closed circuit counts;
- queued, leased, retry-scheduled, failed, dead-lettered, and oldest-queued aggregates;
- request, item, input/output unit, cost, and p50/p95/p99 latency aggregates;
- errors grouped only by the closed `ProviderErrorCode` taxonomy;
- current limit, spent, reserved, remaining, currency, and exhaustion behavior;
- active and rollback generations, pin state, write suspension, and safe reason code; and
- retry, dead-letter, and active-alert counts.

Operation IDs, Brain/project/repository IDs, arbitrary error text, provider request/response bodies,
content, prompts, vectors, credentials, and paths are never metric labels. HTTP request models are
strict and authenticate before scope or repository access. Problem responses contain only stable
types and generic detail.
