PRO-004 prevents vectors with different semantic meaning from sharing physical search state. A space
is the content address of every input, model, tokenizer, preprocessing, numeric, purpose, instruction,
runtime, and execution coordinate that can change the meaning of an embedding. Each Brain owns its
space record and receives at most one generation for a given immutable fingerprint. Different
Brains, spaces, or semantic revisions receive different generation identities and UUID-derived
Neo4j labels and index names.

## Architecture

The implementation follows the Clean Architecture boundary:

- `providers.domain.embedding_spaces` owns the closed descriptor, content fingerprint, immutable
  space, physical generation, vector record, batch, state, and injection-safe naming rules.
- `providers.domain.embedding_space_ports` owns the canonical repository, derived-store provisioner,
  atomic vector writer, identity generator, reservation, and receipt contracts.
- `providers.application.embedding_spaces` owns authorization and the ensure/write use cases. It has
  no SQL, Cypher, FastAPI, driver, or provider-vendor dependency.
- `SqliteEmbeddingSpaceRepository` is the canonical repository and attestation gate.
- `Neo4jIndexGenerationProvisioner` and `Neo4jVectorWriteRepository` are separate derived-store
  adapters. Neo4j never decides which space or generation is active.
- `embedding_space_http_api` authenticates the local capability, resolves current Brain authority,
  requires exact idempotency, and maps typed errors to content-free problem responses.
- `operations.bootstrap` is the sole production composition root.

Every dependency is injected through a narrow port. The domain and application layers do not branch
on OpenAI, Cohere, Qwen, Google, Voyage, or any other provider name.

## Immutable semantic identity

`EmbeddingSpaceDescriptorV1` has no implicit defaults. It includes the adapter identity and digest,
endpoint class, model and immutable revision/weight evidence, tokenizer identity and digest, pooling,
preprocessing and normalization contracts, chunking and truncation, dimension, dtype, encoding,
vector normalization, similarity, provider-output quantization, inference settings, purpose,
query/document asymmetry, instruction digest, runtime image digest, deterministic-inference flag,
execution class, and residency class.

The descriptor uses the closed JSON subset supported by RFC 8785 canonical JSON: UTF-8 object keys and
values, booleans, integers, strings, explicit nulls, and no floating-point coordinate. Keys are sorted,
separators are fixed, non-ASCII text is preserved, and non-finite JSON is rejected. The lowercase
SHA-256 of these canonical bytes is `immutable_fingerprint`. A field delta creates a new fingerprint;
database IDs, credentials, display names, health, quota, and price do not alter it.

SQLite stores Brain ownership, the canonical descriptor bytes, and extracted integrity coordinates.
Immutable triggers reject updates or deletes. A unique `(brain_id, fingerprint)` pair prevents two
database identities for the same semantic space inside a Brain while preserving tenant isolation.
The repository decodes and revalidates every persisted aggregate instead of trusting column values.

## Live provider evidence

An ensure request is accepted only when its provider profile is active and its exact schema-v2
capability attestation remains current. The repository verifies Brain/profile ownership, active probe
identity, adapter/model/revision or weight evidence, adapter digest, execution class, dimension,
dtype, normalization, similarity, and purpose. Stale configuration or probe evidence fails before a
space, operation, generation, domain event, outbox message, or audit record commits.

The HTTP request never contains a credential value. The response contains only immutable identifiers,
fingerprint, generated physical names, dimension, similarity, state, and time.

## Generation identity and physical index

Only a validated RFC 9562 UUIDv7 can produce physical names:

- label: `AMVector_<32 lowercase UUID hexadecimal characters>`;
- vector index: `am_vec_<32 lowercase UUID hexadecimal characters>`;
- vector property: `embedding`.

No provider, model, user, project, repository, path, or arbitrary request text is interpolated into
Cypher. The Neo4j migration enforces unique space fingerprint, generated label, and vector-index name.

The provisioner first creates or verifies complete Brain-bound `EmbeddingSpace` and
`IndexGeneration` metadata. This mirrors canonical SQLite: identical semantic descriptors retain the
same content fingerprint across Brains, while each Brain owns distinct space and generation
identities and a dedicated physical index. It then creates one vector index with exact dimension,
similarity, label, and property. Physical storage quantization is explicitly pinned to `none`; Neo4j
2026.06 otherwise defaults to scalar quantization. Provider-output quantization remains a separate
semantic descriptor coordinate and therefore still creates a separate space/generation. The
provisioner waits for `ONLINE`, reads the actual index contract with `SHOW VECTOR INDEXES`, and
refuses dimension, similarity, quantization, label, property, name, metadata, or state drift.

The Neo4j behavior is pinned to the release image and syntax documented by the
[Neo4j vector-index manual](https://neo4j.com/docs/cypher-manual/current/indexes/semantic-indexes/vector-indexes/).

## Atomic vector writes

`VectorWriteBatch.create` performs all validation before opening a graph transaction:

1. one non-empty batch of at most 1,000 records;
2. exact space, generation, Brain, purpose, dimension, and active writable state;
3. float values only, finite values, bounded magnitude, nonzero norm, and declared normalization
   tolerance;
4. no duplicate record or idempotency identity;
5. exact immutable source-content hash and classification coordinates; and
6. no padding, truncation, projection, conversion, or cross-space reuse.

The deterministic idempotency identity binds Brain, source entity, source-content hash, space
fingerprint, and purpose. The batch digest binds record identity and each float's exact hexadecimal
representation.

The Neo4j repository revalidates the batch and runs four checks in one managed transaction:

1. exact space/generation/index binding;
2. exact current source content, project, repository, checkout, and classification;
3. exact compatibility of any existing immutable vector, including all vector values; and
4. generated-label write cardinality and an exact post-`MERGE` compatibility predicate, closing the
   concurrent-create race between preflight and write.

Any mismatch raises a typed conflict from the transaction callback, causing the official driver to
roll back the entire batch. An exact replay has one effective VectorRecord; divergent content never
overwrites it. Optional checkout identity uses explicit null-safe equality in both compatibility
checks, so checkout-less records remain idempotent under Cypher's three-valued logic.

## Durable lifecycle, idempotency, and audit

The canonical ensure lifecycle is `creating -> populating`. Later backfill, shadow validation,
activation, rollback, and retirement are owned by PRO-008 and must not bypass this foundation.

SQLite serializes reservation with `BEGIN IMMEDIATE`. The request digest binds Brain, profile,
attestation, and space fingerprint. An exact operation replay returns the original reservation;
divergent reuse conflicts. Concurrent operations for the same Brain/space converge on the same
immutable generation through unique constraints and serialized writes.

The same transaction that ensures or publishes the generation also appends:

- an `EmbeddingIndexGenerationEnsured` or `EmbeddingIndexGenerationPopulating` domain event;
- a content-free CloudEvents-compatible outbox message; and
- a central hash-chained `provider.embedding_space.*` audit fact.

The outbox payload contains identifiers, hashes, physical names, dimension, similarity, state, and
request digest only. It never contains source content, vectors, instructions, credentials, prompts,
provider responses, paths, or arbitrary exceptions.
