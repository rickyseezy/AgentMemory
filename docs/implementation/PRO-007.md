PRO-007 makes provider failure behavior deterministic and semantically safe. It does not treat every
HTTP failure as retryable and never substitutes a model merely because it implements the same vendor
operation. A fallback endpoint must be bound to the same immutable output contract, exact live
profile revision, capability attestation, endpoint identity, and embedding space before any request
can reach it.

## Canonical error and retry policy

`ProviderErrorCode` is the single closed taxonomy used by every built-in adapter, retry decision,
circuit transition, terminal result, and degraded-recall translation. `ProviderErrorPolicy` contains
an exhaustive reviewed matrix for authentication, permission, configuration, capability, missing
model, oversize, rate limit, quota, timeout, cancellation, transient upstream, malformed response,
dimension mismatch, model drift, privacy denial, and adapter crash. Composition fails if a new code
is introduced without explicit retry, fallback, and circuit traits.

The production retry policy is one layer with at most three total attempts, matching the normative
configuration in the technical requirements. It applies bounded exponential full jitter with
separate transient and throttling bases. The jitter seed binds the stable downstream idempotency key,
exact endpoint fingerprint, and attempt number. A normalized absolute `Retry-After` time is a
minimum, never permission to exceed the caller deadline. Nonretryable codes fail immediately;
attempt or deadline exhaustion becomes an immutable terminal failure.

The internal provider gateway parses only the normalized `retry_after_microseconds` field from its
strict authenticated response envelope. Vendor headers, bodies, URLs, and credentials never cross
the gateway boundary or enter an exception, API response, audit fact, or retry record. The policy
follows the `Retry-After` semantics in [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html) and
the bounded full-jitter design described by
[AWS retry guidance](https://docs.aws.amazon.com/sdkref/latest/guide/feature-retry-behavior.html).

## Equivalent endpoint authority

`ProviderOutputContract` binds every semantic coordinate that can change output:

- embedding-space ID and immutable fingerprint;
- exact model revision and revision fingerprint;
- operation and canonical purpose;
- preprocessing digest;
- vector dimension, dtype, normalization, and similarity when embedding;
- conformance suite, canary, and validation digests.

`ProviderEndpointAttestation` adds the exact profile ID/version, active capability-attestation ID,
endpoint fingerprint, configuration digest, and certified adapter digest. `EquivalentEndpointSet`
requires every ordered endpoint to have an identical output contract and rejects duplicate profile
or endpoint identities. The set is content-addressed and bounded to 100 total endpoints.

Publication is not self-attestation. `SqliteProviderResilienceRepository` joins each submitted
coordinate to the current canonical provider profile, active probe evidence, capability attestation,
and embedding-space record. A stale profile, replaced probe, different Brain, model drift, changed
shape, different purpose, or changed validation evidence conflicts before insertion. Exactly one set
may bind a primary profile revision and embedding space; changing fallback membership or rank
requires a new provider revision and probe. Internal dispatch resolution repeats the current
authority check so historical evidence cannot authorize a stale endpoint.

Publication uses an immutable operation receipt whose request digest binds Brain and set identity.
Exact replay returns the original set; divergent operation reuse conflicts. Owner or administrator
authority is required to publish. Owner, administrator, or auditor authority may read. Authentication
precedes scope resolution, reads hide cross-Brain existence, and HTTP responses contain only
content-free attestation coordinates.

## Idempotent resilient execution

`ExecuteResilientProviderOperation` binds payload count and SHA-256 digests to the complete immutable
provider operation. It also requires the exact named model revision, canonical query/document
purpose family, and SHA-256 preprocessing-contract identity to match the attested output contract;
an embedding query therefore cannot execute against a document space even when every vector shape
coordinate happens to match. Payload buffers are excluded from representations. The handler
atomically claims the persistent provider operation identity before dispatch and forwards the same
`am-provider-v1:<cache-key>` downstream key to primary and fallback endpoints.

For each allowed endpoint, the handler:

1. acquires the durable circuit or sole due half-open probe;
2. appends a content-free `started` dispatch fact;
3. executes the exact endpoint with the unchanged idempotency key;
4. atomically commits the content-addressed result before reporting success;
5. records circuit success/failure and the canonical outcome code; and
6. either attempts a proven-equivalent fallback, schedules one durable retry, or commits one
   immutable terminal failure.

An arbitrary adapter exception becomes `adapter_crash`; its message is discarded. Cancellation
releases the exact half-open permit, returns the operation claim to retryable state, records only the
closed cancellation code, and propagates cancellation. A completed semantic operation replays from
cache without another charge. A terminal semantic failure also replays without reclaiming or
calling a provider. Crash recovery reuses the same downstream key.

## Durable circuits and evidence

Circuit state is keyed by exact endpoint fingerprint and bound to the endpoint-attestation digest.
The production policy opens after five qualifying failures in 30 seconds and permits one probe after
30 seconds. State transitions are versioned and serialized in SQLite. Closed, open, and half-open
rows have database constraints that reject incoherent timers or probe flags. Rate limiting does not
poison a closed circuit; availability, malformed-output, dimension, model-drift, and adapter-crash
behavior follows the exhaustive error matrix.

Endpoint sets, endpoint members, publication receipts, dispatch facts, and terminal provider
failures are immutable. Circuit state is the only mutable PRO-007 record. Downgrade refuses to
discard any resilience authority or evidence. The migration also advances the Core readiness head
to `0040_pro007_provider_resilience`.

## Recall degradation

`ProviderRecallSource` is the narrow translation between provider-platform outcomes and the PF-004
channel-isolation contract. Retry scheduling, terminal provider unavailability, adapter failure, and
resilience-store outage become `RecallDependencyError` for that optional channel. The structured
recall handler continues exact, lexical, and graph sources and returns the vector channel as degraded
with freshness evidence. Endpoint-equivalence conflict becomes `RecallIntegrityError` and fails
closed; integrity and authorization failures are never concealed as ordinary degradation.

## Clean Architecture and SOLID boundaries

- `providers.domain.resilience` owns the pure error matrix, retry decisions, output contracts,
  equivalence identities, dispatch facts, and circuit state machine.
- `providers.domain.resilience_ports` owns endpoint execution, equivalence, circuit, and evidence
  capabilities without infrastructure imports.
- `providers.application.resilient_execution` owns claim, endpoint selection, fallback, retry,
  terminal failure, cancellation, and evidence orchestration.
- `providers.application.resilience` owns authorized publication and lookup use cases.
- `sqlite_resilience` and `sqlite_operation_cache` implement canonical persistence.
- `resilience_http_api` translates strict authenticated transport contracts.
- `resilience.infrastructure.ProviderRecallSource` is the anti-corruption adapter that translates
  provider errors to channel-specific PF-004 behavior without coupling either application layer.
- `operations.bootstrap` is the production HTTP composition root.

The domain and application layers import no FastAPI, SQLAlchemy, HTTP client, Neo4j driver, vendor
SDK, or concrete provider implementation. Each dependency is a narrow substitutable port, keeping
retry, circuit, equivalence, persistence, gateway, and recall responsibilities independently
testable.

## Fail-closed activation boundary

The authenticated equivalence administration API and its SQLite authority are composed in Core.
The billable execution handler is intentionally available only behind
`ProviderEndpointGateway`. Core does not start the PRO-006 provider scheduler with a placeholder or
direct vendor adapter: PRO-009 must first bind the per-operation egress authorization, isolated
runtime, protected-result manifest, and provider-gateway containment required before a network
socket may be acquired. This sequencing is a security invariant, not an omitted retry path.
PRO-007's executor is the mandatory retry/circuit/equivalence wrapper that the PRO-009 production
gateway must bind; no enabled path may bypass it.
