## Architecture and decision authority

IDX-006 introduces one content-policy domain service for every repository source. The domain owns
immutable policy revisions, ordered rule sources, content-free decisions, and reconciliation
actions. Application handlers own current authorization, activation, source preparation, decision
recording, and work delivery through narrow ports. Git/workspace discovery, SQLite, HTTP, code
projection, and assertion evidence remain outbound or inbound adapters.

The closed precedence order is:

1. an explicit Brain rule;
2. the repository's `.agentmemoryignore` rule source;
3. private-block classification;
4. the repository's `.gitignore` rule source; and
5. generated, vendored, policy-metadata, binary, encrypted, and default rules.

The last matching line wins within an ignore source. A negated ignore rule cancels that source's
exclusion and falls through to the next safety layer; it does not become a global include. A Brain
include is the administrator's explicit highest-precedence content override. Structural safety is
evaluated before all content rules: symlinks are never followed and a descriptor whose reported
size exceeds the active maximum is never opened. Unterminated private start markers fail closed.

## Pre-read and egress boundary

`GitIncrementalRepositorySource` and `LocalWorkspaceSnapshotSource` require a
`RepositoryContentPolicyGate`; there is no permissive default constructor. Each source:

1. discovers bounded `.agentmemoryignore` and `.gitignore` source documents;
2. resolves the active Brain revision and hash-bound source versions;
3. normalizes each repository-relative path and records its path decision before content access;
4. refuses symlinks and oversized Git blobs before opening them;
5. performs one bounded read only for path-authorized content;
6. records the content decision before releasing bytes; and
7. returns only included artifacts to parsing, persistence, embedding, graph, or provider callers.

Git enumeration deliberately observes ignored untracked files instead of letting Git silently
discard them, so the central policy produces auditable decisions. Policy files are read only as
bounded authority documents and are themselves excluded from indexing. Source-session identity
includes the complete policy digest, forcing a safe full scan when Brain or repository rule sources
change. A later `read` reauthorizes the requested revision, preventing a stale manifest from
bypassing a newly tightened policy. Boundary tests use file-open and remote-egress spies to prove
excluded bytes never cross either boundary.

## Immutable evidence and activation

Every `PolicyDecision` records repository/path, phase, disposition, closed reason/layer, exact rule
ID and version, rule-source hash, complete policy digest, observed byte length, optional content
hash, classification booleans, and UTC decision time. Canonical JSON and the decision ID are
deterministic. No source bytes, rule-source bytes, private fragments, or credential values are
stored in decision evidence.

Migration `0031_idx006_content_policy` installs append-only ledgers for:

- immutable Brain policy revisions and parsed repository rule-source versions;
- path/content decisions;
- idempotent policy changes;
- bounded deletion and reindex work with append-only lease snapshots; and
- derivative-invalidation and reindex projection receipts.

SQLite triggers reject update/delete on every ledger. The downgrade is permitted only while all
IDX-006 ledgers are empty. Activation requires owner/admin authority for exactly one Brain, Project,
and Repository; the policy must be exactly the next version. An exact operation replay returns the
original result, while divergent reuse conflicts. Repository policy source versions are monotonic
and hash-idempotent.

The authenticated local API exposes:

- `POST /v1/indexing/content-policies/revisions`, with an `Idempotency-Key` equal to
  `operation_id`; and
- `GET /v1/indexing/content-policies/changes/{change_id}`, with current exact repository scope.

Responses contain policy/change identities and scheduled counts only. Both routes are composed in
the production local Core and deterministic OpenAPI export.

## Policy changes and derivative visibility

Activation classifies every previously observed path in a transaction bounded to 250,000 paths.
Previously included paths conservatively receive deletion work; paths still eligible under the new
path policy also receive reindex work, while newly eligible paths receive reindex work. This
conservative strategy is required because private, binary, and encrypted classification cannot be
replayed from content-free evidence alone.

The worker uses five-minute leases and append-only queued/claimed/completed snapshots. Expired work
is reclaimable. Deletion records the exact semantic IDs, dependent fact IDs, and assertion-evidence
IDs invalidated for the source path. Code-index reads immediately exclude an invalidated revision
until a later final content-include decision exists. Assertion resolution treats invalidated source
evidence as revoked, so graph-derived results cannot keep exposing a policy-excluded derivative.
Reindex work produces an idempotent request bound to path and policy digest.
