# PRO-001 implementation record

| Field | Value |
|---|---|
| Story | PRO-001 — Configure certified built-in providers |
| Delivery status | Repository implementation complete |
| Release status | Remote-provider activation additionally requires the controlled live-provider certification campaign and the PRO-009 gateway runtime |
| Canonical authority | SQLite provider profile, immutable revision, probe, operation, audit, AgentEvent, and outbox records |
| Built-ins | OpenAI, OpenAI-compatible, Cohere, Voyage, Google Gemini, and Qwen local |
| Public interface | Authenticated create, probe, and get profile operations under `/v1/providers/profiles` |
| Relational schema | `0032_pro001_provider_profiles` |

PRO-001 provides one vendor-neutral configuration and activation lifecycle for embedding and
reranking providers. A profile is immutable configuration, not a bag of mutable environment
variables. It remains `draft` until the exact certified adapter manifest is revalidated and a live
probe returns bounded, content-free capability and model-revision evidence. Activation appends a new
revision; it never edits or deletes earlier evidence.

The default installation remains offline and uses the release-pinned Qwen embedding and reranking
sidecars. Configuring a remote profile does not enable egress by itself. The remote gateway remains
the only permitted network boundary and must independently authorize its endpoint policy and
credential references before a probe can reach a provider.

## Clean Architecture boundaries

- `providers.domain.profiles` owns the closed operation, execution, purpose, vector, manifest,
  configuration, probe-evidence, profile-state, and model-drift rules.
- `providers.domain.profile_ports` owns the profile repository, adapter registry, adapter probe,
  local probe, identity, and gateway transport ports.
- `providers.application.profiles` owns `CreateProviderProfileCommand`, `ProbeProviderCommand`, the
  profile query, authorization, idempotent replay, manifest revalidation, and activation
  orchestration.
- `providers.adapters.builtins` contains one vendor protocol adapter per provider. The shared base
  owns only conformance behavior; it contains no routing or product policy.
- `SqliteProviderProfileRepository` is the canonical repository and single transaction boundary.
  It performs current Brain-wide authorization again inside the transaction.
- `profile_http_api` is the strict authenticated inbound adapter. It never returns endpoint,
  approval, or credential references.
- `ProviderGatewayHttpTransport` addresses only `http://provider-gateway:8080`, authenticates with a
  protected local capability, rejects redirects/path escape, and sends opaque references rather
  than credentials.
- `QwenProfileProbeAdapter` translates the existing release-attested PF-001 local sidecar probes
  into the same `ProviderProbeResult` used by remote providers.

Import Linter enforces the provider/domain/application dependency direction with the same blocking
contracts used by every other bounded context.

## Configuration and activation invariants

Every profile binds:

- one UUIDv7 Brain and profile identity;
- one exact adapter ID, operation, explicit model ID, execution class, and sorted unique purpose set;
- bounded batch, byte, token, and timeout limits that can only narrow the certified manifest;
- one immutable certified manifest digest; and
- for remote execution, all of endpoint policy reference, credential reference, owner egress
  approval reference, versioned retention/training/residency declaration, quota, and budget.

Local profiles reject every remote-only field. Remote profiles reject a missing or malformed field.
Only opaque `secret://`, `policy://`, and `approval://` references enter canonical configuration;
credential values are not present in the domain model, command, API schema, database writes,
integration events, audit facts, errors, or responses.

Create validates the installed manifest without network access and persists version 1 as `draft`.
Probe reloads the current revision, revalidates the same manifest digest, executes the adapter's live
protocol canaries, content-addresses the result, and compare-and-swaps the expected profile version.
Create and get return a strong profile ETag. Probe requires that exact `If-Match` value and verifies
both the version and snapshot digest before network access, then repeats the version check in the
repository transaction.
The transaction writes the current snapshot, immutable revision, immutable probe, idempotency
receipt, CloudEvents-compatible outbox record, source AgentEvent, and hash-chained audit event
together. Failure rolls back all of them.

An active profile pins the gateway-attested `revision_fingerprint`. A later probe with the same model
ID but a different fingerprint raises `ProviderModelDriftError`; it cannot update the active profile.
The operator must create a new profile and use the governed embedding-space migration stories for a
model change. Probe timestamps are monotonic and UTC.

## Built-in protocol matrix

| Adapter ID | Operations | Wire contract | Canonical purpose mapping |
|---|---|---|---|
| `openai` | embedding | strict `POST /v1/embeddings` | purpose is encoded into the fixed canary input |
| `openai-compatible` | embedding | exact OpenAI response/order/model contract | same strict mapping; no permissive coercion |
| `cohere` | embedding, reranking | `POST /v2/embed`, `POST /v2/rerank` | query/document/classification/clustering input types |
| `voyage` | embedding, reranking | `POST /v1/embeddings`, `POST /v1/rerank` | query/document or provider-neutral input type |
| `google` | embedding | `models.batchEmbedContents` | Gemini task types, including code retrieval query |
| `qwen-local` | embedding, reranking | authenticated release-pinned local sidecar probe | exact requested canonical purposes |

Every remote adapter probes every configured purpose using two fixed non-sensitive ordered canaries.
It requires exact response count/order, finite floating-point vectors, consistent dimension, one
stable model revision/fingerprint, and verified cancellation. Rerank adapters require every input
index exactly once and a finite relevance score. The profile records capability evidence only; no
canary output vector or provider response body is persisted.

The implementation follows the current official provider contracts:

- [OpenAI embeddings API](https://platform.openai.com/docs/api-reference/embeddings)
- [OpenAI API data controls](https://platform.openai.com/docs/models/default-usage-policies-by-endpoint)
- [Cohere Embed v2](https://docs.cohere.com/v2/reference/embed) and
  [Cohere Rerank v2](https://docs.cohere.com/v2/reference/rerank)
- [Voyage text embeddings](https://docs.voyageai.com/docs/embeddings) and
  [Voyage reranking](https://docs.voyageai.com/docs/reranker)
- [Google Gemini embeddings API](https://ai.google.dev/api/embeddings)
- [Qwen3 Embedding and Reranking](https://github.com/QwenLM/Qwen3-Embedding)

Vendor limits in manifests are conservative certification ceilings, not a claim that every vendor
model accepts the ceiling. The explicit model is validated by the live probe. A provider API change
requires a new implementation version/digest and conformance certification.

## Canonical error behavior

Provider adapters expose only closed error codes: authentication, permission, invalid configuration,
unsupported capability, missing model, oversized input, rate limit, quota, timeout, cancellation,
transient upstream, malformed response, dimension mismatch, model drift, privacy denial, and adapter
crash. Exceptions never include upstream bodies, URLs, headers, credentials, or arbitrary exception
messages. The HTTP adapter maps authorization to 403, immutable conflicts/model drift to 409,
dependency failure to 503, and safe validation/provider rejection to 422.

## Persistence and replay

Migration `0032_pro001_provider_profiles` creates:

- `provider_profiles` for the current manifest-bound snapshot;
- `provider_profile_revisions` for append-only version history;
- `provider_probe_evidence` for content-addressed live attestations; and
- `provider_profile_operations` for exact create/probe response replay.

SQLite constraints enforce enum values, digest shapes, JSON validity, activation/probe consistency,
foreign keys, and one probe per profile revision. Update/delete triggers protect revisions, probes,
and operation receipts. Downgrade is allowed only when no provider profile exists; otherwise it fails
closed. Operation replay returns the historical result revision even when the current profile has
advanced, and reuse with different input, kind, Brain, profile, or expected version conflicts.

Integration topics follow the normative local naming contract:

- `am.local.<brain>.provider.profile-created.v1`
- `am.local.<brain>.provider.profile-activated.v1`

The payloads are CloudEvents-compatible and contain digests, IDs, status, model revision, and
capability evidence only. They contain no provider policy or credential reference.
