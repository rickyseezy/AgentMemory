PRO-005 provides deterministic provider selection without embedding vendor logic in the domain or
application layers. An administrator publishes a complete immutable replacement policy. Every rule
is bound to an exact active provider profile version and snapshot digest. A profile change,
re-probe requirement, capability change, authorization epoch, policy revision, or repository
restriction revision therefore invalidates cache reuse and cannot silently alter a prior decision.

## Precedence and ambiguity

The documented precedence tuple is `(project_specificity, constrained_dimensions)`.
Project-specific rules outrank Brain-wide rules. Inside the same project tier, the rule constraining
the greatest number of corpus, language, classification, purpose, and workload dimensions wins.
Operation is always an exact required match and is not counted in specificity.

Publication rejects any pair of enabled, overlapping, same-operation rules with equal precedence.
There is no declaration-order, database-order, UUID, or last-write tiebreaker. Disabled routes do not
participate. Resolution selects the unique most-specific rule once; a privacy or capability failure
on that rule fails closed and never falls through to a broader route.

## Privacy and capability lattice

The Brain guard owns the maximum remote-egress grant, allowed provider residencies, and remote
classification ceiling. `local_only` data never leaves the device. A remote profile must use one of
the explicitly allowed residencies and the request classification must remain below both the Brain
and repository ceilings.

A repository restriction is filter-only. It can disable remote use, reduce regions or classification,
or allowlist profiles, purposes, and workloads. Its constructor and publication handler reject every
attempt to broaden the Brain guard. It cannot add a route or provider.

Each selected profile must still be active and match the rule-bound profile ID, version, snapshot
digest, operation, and requested purpose. Wildcard-purpose routes are legal, but the selected
profile's live capability is checked for each request. Drift fails closed.

## Clean Architecture

- `providers.domain.routing` owns selectors, precedence, overlap, policy lattice, immutable policy,
  profile projection, requests, decisions, and cache identity.
- `providers.domain.routing_ports` owns repository, identity, and cache abstractions.
- `providers.application.routing` owns exact authorization, policy/restriction publication, profile
  binding, cache orchestration, and durable resolution evidence.
- `SqliteProviderRoutingRepository` is the canonical repository and revalidates every decoded object
  and extracted column.
- `BoundedProviderRouteCache` is a concurrency-safe LRU adapter; correctness never depends on it.
- `routing_http_api` authenticates first, resolves current scope, requires an exact idempotency key,
  uses strict closed request models, and emits content-free problem responses.
- `operations.bootstrap` is the sole production composition root.

The domain and application layers import no SQLAlchemy, FastAPI, provider SDK, Neo4j driver, or
vendor-specific adapter.

## Durable evidence and replay

Policies, normalized rules, repository restrictions, operation receipts, and route decisions are
append-only and protected by database triggers. Rules have a composite foreign key to the exact
provider profile revision. Policy and restriction publication use `BEGIN IMMEDIATE`, compare the
expected current version, and append the new revision, idempotency receipt, domain event,
CloudEvents-compatible outbox message, and central hash-chained audit record in one transaction.

Exact operation replay returns the original immutable result. Reusing an operation identity with a
different Brain, kind, or request digest conflicts. Every resolved response, including a cache hit,
is recorded as content-free decision evidence binding operation, policy, rule, profile version,
request digest, authorization versions, cache-key digest, principal, and time.

## Cache contract

The cache key hashes:

- request digest;
- routing policy version and complete policy digest;
- grant version, authorization-policy version, and security epoch;
- every enabled referenced profile ID, version, and snapshot digest; and
- repository restriction version and digest.

Changing any coordinate creates a miss. Cache entries have a hard capacity, are protected by an
async lock, and evict least-recently-used entries. A hit skips only pure policy evaluation; it never
skips current authorization, policy/profile/restriction reads, or the durable decision journal.
