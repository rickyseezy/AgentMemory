## Outcome

ING-003 gives every sequenced canonical event an explicit causal decision before a projection side
effect can run. The live consumer maintains one Brain/projection/ordering-key watermark, serializes
the next sequence with a compare-and-set lease, waits for missing predecessors, and permanently
records a declared gap when the stable timeout expires. An event arriving at or behind an advanced
watermark is never applied opportunistically: it is retained as `replay_required` and linked to
durable gap and audit evidence.

Operators can select a Brain-scoped event/time range and immutable projection generation/code
fingerprint. Creation captures the exact selected event IDs and their deterministic causal ordinals
inside the same SQLite transaction as the run. The worker then replays that immutable snapshot with
the same pure reducer used by live ingestion, writes only operation-isolated shadow history/state,
and compares deterministic generation digests. A matching generation becomes `ready`; a divergent
generation becomes `superseded`. Neither outcome mutates a live watermark or silently activates
partial state. A divergent replay is evidence for the governed PF-002 full projection rebuild path.

## Clean Architecture and SOLID boundaries

- `ingestion.domain.ordered_replay` owns closed order/replay states, exact evidence records, replay
  range validation, canonical digests, and the pure reducer. It imports no SQL, HTTP, provider,
  framework, clock, or another bounded context implementation.
- `ingestion.application.durable_processing` asks the ordering repository for a decision before it
  invokes the live verifier. Busy, missing-predecessor, and late-event branches perform no projection
  side effect.
- `ingestion.application.ordered_replay` owns authorization, durable claim/resume, bounded paging,
  reduction, validation, and worker failure containment through narrow ports.
- `DurableEventProcessingRepository`, `OrderedReplayAccessPolicy`, and `OrderedReplayRepository`
  separate live arbitration, authorization, and replay persistence. Application code depends only on
  these capabilities.
- `SqliteDurableEventProcessingRepository` commits the projection, inbox/outbox completion,
  reduction history, watermark, and audit fact atomically. `SqliteOrderedReplayRepository` owns the
  immutable source snapshot, isolated shadow generation, validation evidence, recovery, and replay
  audit facts.
- The FastAPI adapter translates strict content-bounded requests and content-free responses. The
  outer composition root is the only place that selects SQLite and starts the replay worker.

These boundaries keep causal policy testable without infrastructure, preserve Dependency Inversion
and Interface Segregation, and allow a future canonical store or transport adapter without changing
the reducer or use cases. Import-linter enforces the architecture rather than relying on convention.

## Live ordering algorithm

For an event with no sequence, the consumer records immutable reduction history but does not invent a
watermark. For a sequenced event it executes this transactionally serialized decision:

1. create or load the `(projection_name, brain_id, ordering_key)` watermark;
2. if `event_sequence <= applied_sequence`, record late-gap evidence and return
   `late_replay_required`;
3. if another unexpired event owns the key, return `busy`;
4. clear only an expired exact key lease;
5. if the event is the next sequence, claim the watermark and return `ready`;
6. otherwise create or reload a stable gap whose timeout never slides; before timeout return `wait`;
7. at timeout declare the exact missing range, claim the watermark, and return `ready_after_gap`.

Completion compares the original prior sequence/digest plus lease owner/event/sequence before it
advances the watermark. The terminal event projection, projection receipt, inbox completion, outbox
completion, ordered history, watermark, and audit outcome share one `BEGIN IMMEDIATE` transaction.
A stale or reclaimed worker therefore cannot advance causal state.

Waiting retries preserve the first gap deadline. A later predecessor can progress first, after which
the blocked event recomputes its remaining range. Declared gaps are immutable historical evidence;
individual late events are additionally tracked in `ordered_replay_required_events`, so one gap with
multiple late arrivals does not lose per-event repair evidence.

## Deterministic reducer and recorded operations

`reduce_projection(prior_digest, reduction_input, code_fingerprint)` is a pure canonical-JSON SHA-256
function. Its complete input includes event ID, ordering key/sequence, original event schema version,
canonical and projection digests, prior-state digest, immutable code fingerprint, and optional
recorded operation evidence. Live and replay both call this exact function.

A nondeterministic result is represented only by a completed `provider_operation_results` record and
an exact `recorded_reduction_inputs` binding containing operation, provider profile, immutable model
revision, purpose, result digest, and content-addressed result reference. Both live and replay verify
the binding against the provider result before reducing it. Replay has no provider/model port and
cannot call a current model. Missing, incomplete, cross-Brain, changed-version, or changed-result
evidence fails closed instead of fabricating a replacement.

The original `agent_events.schema_version` is retained in live and shadow history and participates in
the digest. Replay therefore does not reinterpret a historical event as the current schema.

## Immutable selection, resume, and validation

The request binds actor, current grant, Brain, projection, UUIDv7 shadow generation, immutable 40/64
hexadecimal code fingerprint, and optional inclusive event/time bounds. Creation authorizes first,
captures the latest committed `(ingested_at, event_id)` watermark, inserts the selected event IDs with
stable ordinals, records the exact count, and seeds each selected key from the latest live state before
its first selected sequence. The source snapshot removes races from later captures, including records
with equal microsecond timestamps.

The closed lifecycle is:

`queued -> building -> validating -> ready|superseded`

`building|validating -> partial -> building` supports recovery. Every append stores one unique source
ordinal and advances the durable processed-count cursor in the same exact-owner transaction. After a
crash, only the expired lease is recovered; already committed shadow history is not duplicated.

Validation sorts final states by ordering key and hashes the code fingerprint, key, applied sequence,
and state digest. It compares the shadow result with the equivalent selected live history. `ready`
requires equal digests and resolves selected late-event evidence; `superseded` requires unequal
digests and keeps late evidence pending. The live projection pointer/watermark is never changed by a
selected-range replay.

## Authorization, API, privacy, and audit

Start, status, replay claim, and validation reauthorize the exact actor/Brain/grant against current
principal, Brain, and validity-window state. Revocation converts active worker work to a resumable,
content-free `authorization_revoked` partial state. The POST boundary requires the UUIDv7
`Idempotency-Key` to equal the body operation ID, rejects unknown/coerced fields, and reads at most 64
KiB. Error documents contain only closed codes/field names; status contains operation metadata,
counts, cursors, digests, states, and timestamps—never events, payloads, prompts, paths, vectors,
provider output, credentials, or arbitrary exceptions.

Ready/superseded completion appends one content-free hash-chained audit fact in the same transaction
as the terminal state. Late-event deferral likewise commits outbox/inbox state, repair evidence, and
its audit fact atomically.

## Migration and rollback policy

Migration `0011_ing003_ordered_replay` adds strict replay-required states and creates immutable source,
provider-evidence, watermark, gap, live history, late-event, run, shadow-history, and shadow-state
tables. Foreign keys, unique causal identities, digest lengths, closed states, lease shapes, range
shapes, and terminal-state shapes are database constraints. Downgrade is refused while any ordering
or replay evidence exists because deleting it would make a later event appear safe to apply twice or
out of order.
