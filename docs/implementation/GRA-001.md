## Outcome

GRA-001 establishes the closed, Brain-scoped foundation used by later assertion, evidence, materialized
edge, temporal, and contradiction stories. Graph nodes use a stable canonical identity and immutable
content revision. Relationships use a closed type registry and carry their own stable identity,
scope, lineage fingerprint, classification, and bitemporal recording fields.

The implementation is agent-neutral. Codex, Claude, Gemini, GLM, and other MCP-capable hosts reach the
same authenticated application query. No host-specific code, prompt, or model identity is part of the
graph authority boundary.

## Clean Architecture and SOLID boundaries

- `graph.domain` owns the closed entity, relationship, classification, query, identity, temporal, and
  validation models. It imports no framework, driver, store, or provider; its port type references the
  foundational identity context's immutable `AuthorizedScope` rather than duplicating authorization.
- `graph.application` owns project/write and exact-read handlers. Handlers depend only on segregated
  `GraphProjectionWriter`, `AuthorizedGraphQuery`, and `ScopedGraphRepositoryFactory` ports.
- `graph.adapters.outbound.Neo4jGraphRepository` implements only closed templates against the official
  async driver and is constructed with one immutable `AuthorizedScope` per operation.
- `graph.adapters.inbound.http_api` authenticates, resolves identity scope, narrows it to `graph.read`,
  and maps typed failures to content-free problem responses.
- `operations.bootstrap` is the composition root. The graph domain and application never construct a
  Neo4j driver or inspect transport concerns.

The graph import-linter contracts enforce inward dependency direction and framework-independent domain
and application layers. These boundaries implement single responsibility, dependency inversion,
interface segregation, and Open/Closed extension through ports without speculative abstractions.

## Closed schema and database enforcement

Migration `0003_gra001_brain_scoped_schema` installs 53 composite uniqueness constraints: one for the
`GraphEntity` base label, one for each of the 40 stable entity labels, and one for each of the 12 closed
relationship types. Every identity is unique on `(brain_id, id)`, which permits the same canonical ID
in different Brains while rejecting duplicates within one Brain. The migration is digest-pinned in the
signed migration bundle and advances the singleton graph schema head only after ordered DDL succeeds.

Neo4j Community supports these composite uniqueness constraints but reserves property existence/type
and node/relationship key constraints for Enterprise. AgentMemory remains local and open-source, so it
does not silently depend on Enterprise-only behavior. Instead:

1. strict frozen domain constructors reject missing, mistyped, non-UUIDv7, non-UTC, invalid interval,
   unknown classification/type, zero/invalid digest, and divergent revision fields;
2. the repository persists an exact closed document and never accepts dictionaries or caller Cypher;
3. every read decodes and validates the untrusted projection again; and
4. startup readiness checks all managed constraints plus required property presence/types, closed
   registries, endpoint labels, endpoint Brain equality, and relationship type agreement.

Consequently a supported product write is rejected immediately. A privileged maintenance write that
bypasses the product repository is detected and prevents readiness before graph service is exposed.
Host administrators remain outside the protection boundary and must follow the runbook.

## Scope, query, and concurrency rules

All repository instances bind one explicit database and one immutable `AuthorizedScope`. Supported
actions are exactly `graph.project` and `graph.read`. Templates include Brain, project, repository,
Checkout, and classification predicates before a row can be returned or modified. Dynamic labels and
relationship types use Neo4j's parameterized closed-name syntax only after enum construction; arbitrary
labels, paths, fragments, database names, and relationship names are never accepted.

Entity projection uses `MERGE` on the constrained `(brain_id, id)` key. A transaction-only nonce
distinguishes the creating writer and is removed before commit. Concurrent exact retries converge on
one node and one revision; a same-key write with different content fails with `GraphConflictError`
without overwriting the first revision. Relationship writes additionally require both endpoints to
exist as authorized `GraphEntity` nodes in the same Brain and scope.

The exact-read HTTP route resolves the current explicit project and repository authorization before
constructing a graph-specific scope. It accepts a closed entity enum and UUIDv7 path ID, returns only
schema metadata, and never exposes properties containing arbitrary graph content.

## Migration, repair, and rollback

Writers activate only after the signed migration bundle, constraint inventory, graph integrity scan,
and existing vector-index compatibility probe pass. The migration is repeatable through `IF NOT
EXISTS`. Existing valid graph records remain in place.

Do not downgrade by dropping constraints under an active writer. To roll back, stop Core and workers,
retain a protected data backup, verify that no later story depends on schema head `0003`, and follow
[the GRA-001 runbook](../runbooks/GRA-001-GRAPH-SCHEMA.md). Prefer a forward repair migration. A malformed
record must be quarantined or rebuilt from canonical SQLite events; it must never be edited into
apparent validity without canonical lineage.
