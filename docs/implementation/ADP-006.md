## Outcome

ADP-006 provides one authorization-first session briefing across every certified agent host. Producer
host, model, adapter ID/version, capture method, classification, evidence event, and semantic content
survive recall unchanged. The consumer host is never passed to `StartSessionBriefingHandler` and
cannot influence memory authorization, candidate access, ordering, deduplication, or selection.

The certified 5-by-5 producer/consumer corpus proves equivalent facts, decisions, changes, failures,
and next steps for all 25 host pairs. The same corpus maps each producer through valid canonical
`AgentEvent` families before projection. A generic or capability-limited adapter can checkpoint the
same semantic units using `explicit_tool_only`; the lower-fidelity capture method remains visible and
does not erase the accessible evidence.

## Clean Architecture and SOLID boundaries

- `retrieval.domain.continuity` owns atomic item, provenance, budget, host-profile, procedure-
  environment, and result values. It has no framework, SQL, crypto, transport, or vendor dependency.
- `retrieval.domain.ports` defines separate `ContinuityReadRepository` and
  `ProcedureReadRepository` interfaces. This separation prevents procedure applicability from
  becoming a hidden memory-access policy.
- `retrieval.application.start_session_briefing` owns deterministic selection. It consumes an
  immutable `AuthorizedScope`, validates every repository result defensively, selects memory first,
  and evaluates structured procedure compatibility afterward.
- `SqliteContinuityReadRepository` applies Brain/project/repository/checkout/classification/time and
  current-grant predicates before content access, checks event/item tombstones, unwraps the local
  Brain key, authenticates AES-256-GCM envelopes, validates the complete canonical event/index
  binding, and projects the versioned continuity fragment.
- `BriefingDeliveryAdapter` is the only host-varying boundary. It clamps the caller budget to the
  certified profile, supplies structured procedure capabilities, and renders typed untrusted data as
  escaped Markdown or canonical JSON without adding, removing, rewriting, or reranking memories.
- The retrieval context is governed by three additional import-linter contracts for layer direction,
  domain independence, and application independence.

## Budgeting and context safety

ADR-012 defaults are 1,200 tokens, 12 atomic items, and 20 KiB. Selection uses a conservative one-token-
per-three-UTF-8-byte counter and a common 64-token/512-byte envelope reservation. Items and procedures
are never cut. An oversized atom is skipped and later eligible atoms may still fit. Memory selection
always precedes procedures, so a consumer capability cannot evict or reveal a memory.

Ordering is unresolved next steps, decisions, failures, changes, then supporting facts; equal items
use occurrence time and stable item identity. Duplicate kind/content atoms collapse deterministically.
Markdown output JSON-escapes angle brackets and labels the entire block as untrusted historical data,
not instructions. Generic JSON carries the same explicit untrusted-data marker.

## Authorization, deletion, and integrity

The HTTP adapter authenticates before resolving an authorization-first identity scope. The SQLite
query parameterizes the complete scope and rechecks an active principal, Brain, and current grant at
read time. A stale in-memory scope therefore cannot survive revocation. Classification and temporal
ceilings are enforced in SQL and again in the application layer. Event tombstones are applied before
decryption; continuity-item tombstones are applied before result assembly.

Canonical ciphertext, wrapped data key, AAD, key identity, content hash, event schema, scope index,
event family, classification, and occurrence time must all agree. Any mismatch is a typed
`AM_INTEGRITY_VIOLATION`; unavailable storage/key access is retryable
`AM_DEPENDENCY_UNAVAILABLE`. Neither error returns content, paths, key material, ciphertext, SQL, or
arbitrary exception text.

## Procedure separation

Memory access is complete before `ProcedureApplicability.exclusion_reason` runs. Applicability uses a
structured platform and canonical capability set, not producer host name. An incompatible procedure
returns a stable content-free reason such as `missing_capability:patch.apply`; the same memory IDs
remain selected. The runtime repository is explicitly empty until the governed learning/procedure
stories introduce active approved procedure projections. This is a closed safe adapter, not an
authorization bypass or implicit universal procedure.
