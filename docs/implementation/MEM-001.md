## Outcome

Completed and checkpointed tasks now create durable automatic consolidation work for an exact task,
terminal event, evidence watermark, and extractor fingerprint. The extractor can propose decisions,
constraints, procedures, preferences, lessons, episodes, and unresolved work, but it cannot write a
memory. Strict decoding and `MemoryPromotionPolicy` make the final deterministic decision and retain
content-free rejection evidence for every schema-valid candidate that policy rejects.

Raw AgentEvents remain immutable, encrypted, and independently reconstructable. MEM-001 adds only a
non-content task index, active memory revision records, evidence links, consolidation receipts,
outbox/audit facts, and durable worker state. It never replaces, summarizes over, or mutates the
canonical event envelope.

## Clean Architecture

- `memory.domain.consolidation` owns bounded task evidence, the closed memory taxonomy, strict
  candidate decoding, confidence and temporal invariants, promotion policy, stable IDs, extractor
  identity, idempotency, and consolidation receipts.
- `memory.domain.work` owns the closed lease/retry/dead-letter lifecycle. Dependency failures retry
  at bounded exponential intervals; authorization, input, and integrity failures stop immediately.
- `memory.domain.lineage_backfill` owns content-free historical progress and lineage records.
- `memory.application.consolidate_task` orchestrates authorize, load, extract, validate, promote,
  reauthorize, and atomically commit through capability-specific ports.
- `memory.application.consolidation_worker` discovers terminal snapshots and contains provider or
  storage failures without terminating the daemon. `lineage_backfill` checkpoints authenticated
  historical events before work discovery becomes eligible.
- SQLite, envelope decryption, and local HTTP are outbound adapters. Domain and application modules
  do not import SQLAlchemy, HTTPX, Pydantic, cryptography, FastAPI, or the provider implementation.

The repository and Unit of Work boundaries enforce Dependency Inversion and Interface Segregation;
separate evidence, access, receipt, mutation, worker, extractor, and backfill ports prevent a broad
storage/service interface. Promotion is Open/Closed over the closed class policy map, and each
adapter has one persistence or transport responsibility.

## Evidence and candidate boundary

`event_task_lineage` is inserted in the same transaction as a newly captured canonical event. It
contains only Brain/scope/principal/task/session/trace/type/classification/retention/time and the
canonical envelope digest. `SqliteTaskEvidenceQuery` selects one exact terminal event, orders all
same-scope task evidence through that terminal, enforces the 256-item/1 MiB bounds, decrypts each
canonical envelope through the existing key hierarchy, authenticates its digest and identity, and
passes only the canonical event payload into the extractor bundle.

Candidate output is strict UTF-8 JSON: bounded, duplicate-key-free, finite, canonical, closed to
unknown fields, and bound to the exact extractor-input SHA-256. A candidate has no authority unless
every evidence ID exists in the bundle and its scope is exact. Integer basis-point confidence avoids
floating ambiguity. The production thresholds are class-specific. Preferences additionally require
explicit prompt/feedback evidence, lessons require outcome/failure/test evidence, and unresolved
work is valid only at a checkpoint.

The local HTTP adapter accepts only `http://local-extractor:8080`, follows no redirect or environment
proxy, authenticates with a protected capability file, enforces the command deadline, bounds framing
and response size, verifies every request identity echoed by the response, and checks output digest.
The provider endpoint pins operation, task, model revision, schema, classification, and input digest;
the llama.cpp backend uses schema-constrained decoding and treats task evidence as delimited data,
not instructions.

## Atomic persistence and idempotency

The normative consolidation key is SHA-256 over length-framed task ID, evidence watermark, and
complete extractor fingerprint. The fingerprint binds extractor ID/version, immutable model ID and
revision, and output schema. Stable memory identity additionally binds candidate key and canonical
content digest.

One `BEGIN IMMEDIATE` Unit of Work reauthorizes the current actor/grant and atomically writes:

- the consolidation receipt and result digest;
- promoted memory aggregate metadata and immutable revision content;
- exact evidence links or content-free policy rejections;
- a canonical `MemoryConsolidated` domain event;
- projection outbox messages; and
- hash-chained audit evidence.

An exact retry returns the authenticated receipt without invoking extraction. A divergent duplicate,
changed evidence digest, stale grant, or extractor response drift fails closed. No model call or
decryption occurs while the write transaction is held.

## Automatic work, interruption, and historical upgrade

`memory_consolidation_work` tracks one immutable terminal/extractor/evidence snapshot with a
compare-and-swap lease. Checkpoints and completion are independent terminal snapshots. New or late
evidence creates a new watermark and therefore new work without mutating an older receipt. Expired
leases recover; dependency/internal errors retry within fixed attempt ceilings; terminal failures
retain only a closed error code.

Migration `0015` creates the write-through task index and a resumable historical backfill. The
backfill captures an immutable `(created_at,event_id)` source watermark under the single-writer lock,
then decrypts and authenticates bounded pages outside write transactions. Each optional lineage row
and cursor/count update commits atomically. It preserves the original source ingestion cursor,
accepts only byte-identical existing lineage, and stops on digest or identity divergence. Events
captured after the watermark use the live write path and are not counted by the historical run.
Automatic consolidation remains gated until the historical state is `completed`, preventing partial
task snapshots from being learned during upgrade.

Downgrade is allowed only while every MEM-001 evidence/work/backfill table is empty. Once durable
lineage, memories, receipts, work, or progress exists, rollback refuses; restore a coherent
pre-upgrade backup instead.
