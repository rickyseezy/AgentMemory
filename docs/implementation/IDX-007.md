## Architecture and evidence contract

IDX-007 adds a source-navigation slice without moving Git, SQLite, FastAPI, or host filesystem
concerns into the domain. `SourceEvidence` is the complete immutable coordinate behind a
code-derived result: Brain, Project, Repository, snapshot, optional full commit, source file, file
revision, semantic evidence, symbol, role, UTF-8 byte/line range, content hash, byte length, parser,
grammar, query-pack, and semantic-source identity. `CodeSearchHit.evidence_id` gives every indexed
symbol result the stable key needed to enter this resolution path.

`SqliteSourceEvidenceRepository` resolves either a symbol definition or occurrence from canonical
IDX-001 rows. It revalidates the current grant and exact Brain/Project/Repository scope before
returning metadata. The shared IDX-006 visibility predicate hides every policy-invalidated path
until a later final content-include decision supersedes the invalidation. Missing, revoked, and
policy-hidden rows therefore cannot be recovered by guessing evidence IDs.

The immutable URI uses the exact full commit when present, otherwise the immutable snapshot ID. It
percent-encodes the repository-relative UTF-8 path and binds the content SHA-256, file-revision ID,
and half-open byte range. It never contains an absolute path and never changes to follow a current
checkout.

## Revision verification and current mapping

`ResolveSourceEvidenceHandler` accepts bytes only through `SourceContentPort`. It verifies the
historical Git/CAS blob's exact length and SHA-256 and validates the persisted byte/line coordinates
against those bytes. If the historical blob is unavailable, exactly one current candidate with the
same full-file digest can establish the revision; a different or ambiguous candidate cannot.

Current mapping is deliberately conservative. The trusted rename/diff adapter supplies only the
same path and Git-proven rename/copy candidates. For changed bytes, the exact historical span bytes
must occur once in exactly one candidate. Duplicate fragments, multiple matching files, inconsistent
checkout commits/dirty states, and absent fragments produce no current mapping. Unicode line and
column coordinates are recomputed from bytes, not decoded character indexes. Mapping distinguishes
exact, renamed, shifted, and renamed-and-shifted results.

The response separately reports the checkout commit, dirty state, mismatch boolean, resolution
state, historical-blob availability, and optional verified mapping. A clean checkout is `exact`
only when its full commit and the mapped file digest/path/span all equal the evidence revision. A
different commit or any staged, unstaged, or untracked change is explicitly a mismatch even when
the supporting file itself is unchanged.

## Ephemeral Git and local-open boundary

`GitSourceContentAdapter` follows the same boundary as IDX-002: trusted repository roots and a fixed
Git executable are supplied by the ephemeral workspace/session composition and are never persisted
or accepted from HTTP/MCP input. Git runs through argv without a shell, with bounded time/output,
file size, and candidate count. Historical metadata is checked before blob reads. Worktree reads
use `lstat`, `O_NOFOLLOW`, inode/device checks, bounded reads, and post-read size/mtime checks.
IDX-006 path and content policy decisions are recorded before bytes leave the adapter.

`BoundedLocalPathResolver` is the explicit UI/CLI open boundary. The caller must replay the exact
immutable URI, mapped relative path, and current content digest it previously accepted. The
application reauthorizes and re-resolves the source link, then the host adapter verifies canonical
root containment, refuses symlinks and path traversal, rehashes the regular file, and returns the
absolute path only transiently. Absolute paths are never stored, logged, included in Core OpenAPI,
or sent to providers.

The persistent Core publishes the content-free
`GET /v1/indexing/source-evidence/{evidence_id}` contract. As with IDX-002 source streaming, the
actual Git and local-open adapters are composed at the PF-005 ephemeral workspace boundary; the
persistent Core is not given a long-lived source-tree mount.

## Failure and privacy semantics

- Authentication precedes scope resolution and evidence lookup.
- Wrong actions, repositories, roles, expired grants, and policy-invalidated paths fail closed.
- Historical hash/length/span disagreement is an integrity conflict, never a best-effort link.
- Missing historical bytes plus a non-exact checkout is dependency-unavailable.
- Current ambiguity returns immutable evidence without a mutable mapping.
- HTTP problems contain stable codes and never echo evidence IDs, paths, source, Git output, or
  adapter exceptions.
- Source bytes stay inside the local application call and are never included in the DTO.
